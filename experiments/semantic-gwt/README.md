# semantic-gwt 브랜치 — RULE·EXAMPLE 의미 층을 검증 가능한 파이썬 표기로

## 원래 목표 (사용자 정의, 2026-08-05 — 이 브랜치의 헌장)

1. RULE·EXAMPLE을 만들 때 LLM이 **자연어로 뱉으면 비교가 불가능**하다.
2. 따라서 **결정론 검증 가능한 표기**(파이썬 유력 — 자연어만 아니면 됨)로 뱉게 한다.
   단, **코드를 파이썬으로 변환하는 것이 아니라, 의미(자연어로 쓸 내용)를 파이썬 표기로** 쓴다.
3. 정답지는 로직으로 만들 수 없으므로 **사용자가 직접 표본 골든셋을 마련**해 대조한다.
4. **전 노드 비교는 불가** — 표본 채점이 전제다.
5. 값은 하지 않는다(확정). 본로직(main)의 구조화·기계검증 층은 그대로 두고 의미 칸만 바꾼다.

## 현재 상태 (2026-08-05)

- 형식 축 성립 확정: 운영 record 276콜 — 파싱 94.5%, 값 창작 0, 기존 검증층(조건·반환 채점) 무손상.
- 의미 축 반복 중 (골든셋 12행, 운영 GPU): v1 given 75%/then 58% → **v2 given 83%/then 75%**
  (여집합 오독·루프 슬라이싱 해결 — 반복 상승 곡선 확인).
- 남은 표적: 누적 `_after` 미적용·저장 누락·entry 초기화 혼입 + 채점기 보정 2건
  (호출 인자 정규화·분기 단위 병합 채점).

## 다음 순서

1. 채점기 보정 → v3 지침 → 재측정
2. 골든셋을 고정 표본 20함수로 확장 (`_runs/ast-contract-20260805/l_sample_framework.json`)
3. **nl(자연어)도 같은 골든셋으로 채점** — 공정 비교
4. 기준(then 정확도 예: 90%) 통과 시 main 합류 설계(spec): rel 칸 도입 형태(대체/병기)·
   파싱 탈락분 선별 재요청·정규형/심볼 채점기 상설
5. 미달 시 병기 또는 보류 — 결론은 측정이 낸다.
