# 01. 절대 계약과 금지

## 1. 권위 순서

1. 사용자의 현재 명시 지시
2. 지금 실행한 코드·로그·DB 결과
3. 프로젝트 memory 원문과 헌법 1.3.2
4. 현재 spec/plan/tasks와 이 정본
5. 과거 핸드오프·과거 spec 절·과거 실험 기록

핸드오프도 증거 없이 믿지 않는다. 충돌하면 현재 실행을 재현하고, 틀린 문서를 수정한다.

## 2. 반드시 지킬 설계 원칙

1. **정확도와 토큰을 맞바꾸지 않는다.** 같은 의미·같은 증거를 더 짧게 표현한다.
2. **한 사실은 한 번만 전달한다.** source, branch evidence, callee summary, CALL/RW/RETURN을
   여러 이름이나 필드로 중복 주입하지 않는다.
3. **모든 언어를 전제로 한다.** 언어 문법·프레임워크 지식은 ontology/skill 데이터에 두고,
   결정론 코드에 언어명·함수 접두·고객 코드값·이름 패턴을 하드코딩하지 않는다.
4. **LLM 성능이 낮다는 전제로 한다.** 충분한 증거를 좌표·짧은 ID로 제공하고, 가능한
   출력은 동적 required key·enum/regex로 강제한다. 부탁형 프롬프트에 의존하지 않는다.
5. **코드는 의미를 하이재킹하지 않는다.** LLM이 빠뜨린 의미를 빈값·기본값·추정값으로
   조용히 채우거나 다른 의미로 바꾸지 않는다.
6. **실패를 숨기지 않는다.** operational failure와 model-quality finding을 구분해 둘 다
   좌표·원인·증거와 함께 표면화한다.
7. **원인은 로그로 확정한다.** 콜별 입력/출력/지연/finish reason/partial/raw, 분기표,
   finding을 조인한 뒤 코드 범인을 고친다. 벽시계 하나만 보고 추정하지 않는다.
8. **해피패스 통과는 증명이 아니다.** 실패·경계·빈 입력·과대 입력·잘못된 모델 출력·
   부분 출력·동시성 경쟁을 반증 테스트한다.
9. **원칙 위반은 범위 밖이라고 보류하지 않는다.** 발견 즉시 tasks에 편입하고 이번 작업에서
   범용적으로 수정한다.
10. **구조 구문의 소유자는 parser다.** ANTLR grammar가 식별할 수 있는 RETURN, CALL,
    ASSIGNMENT, THROW/RAISE, BREAK/CONTINUE, 조건식과 같은 구문 사실은 언어별 listener가
    AST JSON으로 제공한다. analyzer가 특정 토큰·정규식·괄호 수로 다시 파싱하지 않는다.
    언어 차이는 parser listener가 소유하고 analyzer는 언어중립 AST role을 소비·검증한다.

## 3. 제약 (허용 / 제한 / 이유)

제약은 반드시 허용 범위를 함께 적는다. 금지만 적으면 범위가 넓게 읽혀 필요한 작업까지
피하게 된다 — 실제로 "Neo4j 접촉 금지"를 읽기 금지로 해석해 검증에 필요한 조회를
피한 사고가 있었다(2026-08-05 정정). 정본 표현은 08 §4가 소유한다.

| 대상 | 허용 | 제한 | 이유 |
|---|---|---|---|
| Neo4j 기본 DB | **읽기 자유** | 전체 재분석 실행은 `--database test`로만 | 실행은 대상 DB를 비우고 새로 채운다. 기본 DB의 비교 기준선이 덮이면 Stage 8 delta 상대가 사라지고 되돌릴 수 없다 |
| canonical `project\data` | **읽기 자유** | 새 AST 생성으로 덮어쓰기는 검증·승인 후 | 덮으면 구 AST가 사라져 전후 대조가 불가능해진다 |
| dirty WIP | 읽기·다른 위치 편집 | `reset`/`checkout`/`clean`, 사용자 변경 덮어쓰기 | 미커밋 사용자 구현이 공존하며 복구 수단이 없다 |
| 추론 서버 | 요청 수준 파라미터 | 서버 설정·모델·tensor parallel·launch flag 변경 | 통제 밖의 공용 자원이다 |
| 성능 비교 | 응답 캐시 끈 cold | 캐시 켠 상태의 비교 | 캐시 적중이 지연을 가려 인과가 사라진다 |
| 다른 워크스페이스 프로세스 | 상태 확인 | 종료·변경 | 동시 작업이 있을 수 있다. 동시 수정을 감지하면 사용자에게 알린다 |
| 결정론 코드 | 언어중립 role·구조 판정 | 특정 함수·코드값·상태값·접두·고객 샘플·언어명 분기 | 샘플에 맞춘 코드는 다음 코퍼스에서 무너진다 |
| 구조 구문 | parser AST 소비·검증 | analyzer가 정규식·첫 토큰·이름 모양으로 재탐색 | 이중 생산은 어느 쪽이 돌았는지 알 수 없게 만든다 |
| 폐기 확정 설계 | — | 런타임 값·객체 상태 추적, 상태코드 의미 추론, 이름만으로 논리명 확정 | 이미 실측으로 반증됨 |
| LLM 오답 | 좌표별 finding 격리 후 계속 | 같은 내용 재요청, 별도 LLM judge·repair 추가 | 같은 답이 나오고 시간만 든다. 검증자가 같은 한계를 공유하면 검증이 아니다 |
| 품질 위반 1건 | 그 좌표만 격리 | 전체 재분석 종료 | 나머지 작업이 통째로 낭비된다 |
| 실패 후보 | finding으로 표면화 | 빈 성공으로 저장, finding 없이 누락 | 통계가 거짓이 된다 |
| 비밀값·고객 원문 | 요청에 사용 | evidence 폴더 밖 공유, 문서·로그·커밋에 복사 | 유출 경로 차단 |
| 병목 주장 | 측정한 것만 | 측정하지 않은 KV 캐시·GPU·Neo4j 병목 단정 | 추정이 사실로 굳으면 잘못된 수정을 낳는다 |

## 4. 실패 계약

### 전체 단계가 실패해야 하는 경우

- 연결/서버 오류가 제한 transport retry 후에도 복구되지 않음
- 필수 AST/DDL/audit evidence 부재
- budget 초과
- 결정론 불변식 파괴
- 저장/입출력 계약이 깨져 신뢰 가능한 결과를 만들 수 없음

이 경우 error log + stream error + raise가 모두 있어야 한다.

### 전체 단계가 계속되어야 하는 경우

- LLM 후보의 schema, syntax, grounding, semantic 검증 실패
- 허용 symbol/literal 바깥 생성
- required 좌표는 있으나 내용이 틀림
- 후보가 출력 상한 또는 반복 가드에 걸림

이 경우 해당 좌표만 trusted 파생에서 격리하고 finding에 raw/partial, target, evidence,
reason을 남긴다. 독립 작업은 계속한다. 내용 재시도는 하지 않는다.

## 5. 성능 합격 원칙

- 공식 조건: `ROBO_LLM_RESPONSE_CACHE=false`, `ROBO_PIPELINE_MAX_CONCURRENCY=64`,
  Neo4j `test`, 전체 cold rebuild 1회
- 현재 허용선: 18분대
- 개선 목표: 11~15분
- 정확도 바닥: 현재 기준선 trusted 4,016을 낮추지 않고 obligation 4,100·unavailable 0
- wall만 빨라지고 trusted/finding 구성이 악화되면 실패
- 동일 입력의 모델 변동 가능성이 있으므로 한 run 차이만으로 인과를 단정하지 않는다.
  제한 replay와 직접 의미 대조를 함께 사용한다.

## 6. 무한 반복 종료선

1. **모델 내용**: 한 번 생성한다. schema/syntax/grounding/semantic 실패는 재요청하지 않고
   좌표별 finding으로 격리한다.
2. **전송 오류**: 연결·rate-limit·서버 오류 중 usable model output이 전혀 없는 경우만 공용
   runner가 최대 3회 시도한다. partial output, 반복 가드, generation deadline은 내용 실패이며
   동일 요청을 다시 보내지 않는다.
3. **프롬프트/스키마 개선**: 같은 공통 원인에 대해 증거로 확인한 범용 수정은 한 차례만 적용해
   고정 replay로 반증한다. 같은 입력에서 계속 틀리거나 변동하면 model limit/randomness 또는
   needs-context로 기록하고 문구만 바꾸는 반복을 종료한다.
4. **성능 후보**: 한 후보는 고정 A/B와 공식 cold 1회로 판정한다. 서버 변동 때문에 합격 경계가
   불명확할 때만 확인 cold 1회를 추가한다. 변경 없는 cold 반복은 금지한다.
5. **분할/스케줄 후보**: 콜 수·출력 토큰·wall·정확도 중 기대 지표가 개선되지 않으면 즉시 폐기한다.
   더 잘게 쪼개는 동일 계열 실험을 무한히 반복하지 않는다.
6. **성능 종료**: 18분대와 정확도 기준을 만족한 뒤, 남은 개선이 서버/모델 변경이나 정확도 교환을
   요구하면 성능 최적화를 종료하고 전체 검증으로 진행한다. 11~15분은 안전한 범용 개선이 있을
   때만 추구한다.
7. **의미 검증**: 주 에이전트도 입력만으로 확정하지 못하면 `needs_context`로 종료한다. 충분한
   입력인데 모델만 실패하면 범용 수정 1회 후 model limit로 종결한다.
8. **goal 종료**: 열린 항목이 외부 권한·새 명세·모델 확률성 때문에 더 진행할 수 없고 위 종료선을
   충족하면 완료가 아니라 `한계/미검증`으로 보고하고 반복을 멈춘다.
