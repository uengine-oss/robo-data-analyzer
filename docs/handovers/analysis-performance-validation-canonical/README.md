## 한 문장 목표

모든 언어에 유지보수 가능한 범용 analyzer를 만들되, 의미 판단은 LLM에 구조화된 충분한
증거와 강제 출력 틀로 맡기고, 코드는 구조·검증·격리·파생만 담당하며, 정확도를 떨어뜨리지
않고 cache OFF·concurrency 64·Neo4j `test` 전체 콜드를 현재 18분대보다 줄인다.

## 현재 결론

- 사용자 허용선은 **18분대**다. 11~15분은 계속 추구할 개선 목표이지, 정확도를 희생해
  억지로 맞출 합격선이 아니다.
- 최신 정확도 기준선은 run `20260804_144504_260ab2bbc506`의
  `trusted 4,016 + findings 84 = obligation 4,100`, unavailable 0이다.
- 최신 실행 run `20260804_154237_9ec4b55e17b1`은 18분 10.8초였지만
  `trusted 4,006 + findings 94`라 정확도 기준선보다 10행 낮다. 스케줄 순서 실험은 이미
  되돌렸다. 이 run을 정확도 기준선으로 승격하지 않는다.
- 현재 벽시계의 지배 병목은 Rule 호출이다. Rule 747콜 평균 76.2초, 최대 179.4초,
  478콜이 60초 이상이다. Rule 지연과 출력 토큰 상관계수는 0.990이다.
- summary는 이미 대기열 최우선이며, 확정 즉시 상위 함수와 후처리를 깨운다. Rule/Table은
  불필요한 전역 summary 배리어 없이 실행된다. 단순 스케줄 변경은 해결책이 아니었다.
- Rule 원시 JSON의 약 40%가 구조 공백이다. 같은 의미를 보존하면서 구조 토큰만 줄이는
  compact regex가 유력하나, `extra` 1건의 선택 차이가 있어 **아직 미채택·미검증**이다.
- context 전체를 자동 요약하는 범용 compactor는 없다. 최신 C run의
  `[CONTEXT_SUMMARY]` 사용은 0건이다. 중첩 DBMS 경로의 압축 의미 보존은 미검증이다.
- 현재 `summary_contract.md`는 purpose-only인데 생산 summary 하나가 사람 표시·검색·
  bottom-up 전달을 모두 맡는다. 중요한 효과·상태·테이블·반환 의미가 소실될 위험이 있어
  해결 전 항목이다(TA-144).
- 새로 확인된 구조 결함: 현재 Framework AST JSON은 RETURN 노드를 내보내지 않으며 analyzer가
  함수 원문에서 첫 토큰·정규식으로 RETURN/CALL/ASSIGNMENT 일부를 다시 찾는다. parser grammar가
  아는 구문은 `antlr-code-parser` listener/AST JSON이 생산하고 analyzer는 소비·검증만 해야 한다.
  범위와 전환 게이트는 `07-AST-구조사실-생산자계약.md`와 TA-151을 따른다.

## 완료로 착각하면 안 되는 것

- 18분대 도달만으로 전체 목표가 끝난 것이 아니다.
- 단위 테스트 통과만으로 의미 정확도가 증명되지 않는다.
- `cached_tokens=0` 응답만으로 서버 KV 캐시가 없다고 결론 내리지 않는다.
- 논리 입력 토큰 합계가 줄었다고 KV 캐시 적중을 증명할 수 없다.
- 모든 행 키가 required라고 해서 cond/then 참조가 evidence별 enum으로 닫힌 것은 아니다.
- guardrail 위반 후보는 모델 품질 finding이지 전체 run 실패가 아니다.
- AST로 제공 가능한 구조 구문을 analyzer 정규식으로 찾는 것은 범용 구현이 아니다.
