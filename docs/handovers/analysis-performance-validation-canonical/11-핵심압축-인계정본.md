### 1.2 원인 추적 순서 (헌법 X) — 이 순서를 건너뛰면 반드시 틀린다

```
원문 → parser AST → 결정론 조립 → 모델이 실제로 받은 프롬프트
     → 정보 충분성 → 채점기/정답지 → 모델
```

**통계가 아니라 틀린 좌표 하나에서 출발한다. 모델은 마지막 용의자다.**

### 7.5 최상위 원래 작업 정정 — 의미-파이썬 표기 vs 좌표·근거 전달의 Architect A/B

| 전략 | 실제 뜻 | 현재 상태 |
|---|---|---|
| A. 의미-파이썬 표기 | 소스 코드를 Python으로 번역하는 것이 아니다. 자연어 `nl`로 쓸 업무 관계를 `result_after == result_before + amount` 같은 파싱 가능한 Python 관계식으로 표현해 Architect에 준다 | 별도 `feature/semantic-gwt` 브랜치 HEAD `fd1dc89`. 형식 축 276콜에서 파싱94.5%·값 창작0·기존 cond/return 검증 무손상. 12행 의미 골드 v1→v2는 given75→83%, then58→75%라 **채택 미달·진행 중** |

따라서 판정은 “Python 문법이 파싱되는가”나 “좌표가 존재하는가”만 보면 안 된다. 동일한 쇼핑몰

skill·동일 골드에서 **입력 표현만 바꾸고** 다음을 비교한다.

1. 정상·경계·실패 GWT의 필수 의미 포함률과 틀린 의미/창작.
2. 각 Given/When/Then을 원 RULE 행·CALL·R/W·TABLE sample로 역추적할 수 있는가.
3. 중복 bytes, 실제 input/output token, wall time, MCP 호출 수.
4. Simplified와 Detailed 수렴 전후 GWT 보존. 모드는 별도 전략이 아니라 A/B를 통과시키는
   두 Architect 실행 경로다.
