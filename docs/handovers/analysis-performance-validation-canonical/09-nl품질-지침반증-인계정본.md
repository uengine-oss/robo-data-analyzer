## 5. 전체 배선: 입력→변환→저장→소비자

```
C 소스 (framework-data/source, 23파일)
  → parser AST (framework-data/analysis, *.json)               [antlr-code-parser]
  → 분기표 build_inventory()  … 답할 자리 5,210행 결정론 생성    [branch_inventory.py]
  → 행 증거 rule_evidence()   … conditions(C##)/effects(E##)/rows(when,direct)
                                 ↑ 이 문서가 다루는 SWITCH 수리 지점
  → 프롬프트 조립  [고정 계약(rule_leaf_contract.md) → TARGET → 행 증거]  ← KV 캐시 순서
  → LLM 응답  {R###: {cond:[refs], then:[refs], nl:"문장"}}
  → 결정론 채점 rule_grading  … cond==when? 필수 ret 포함?  실패 시 좌표별 격리
  → 통과분만 RULE 노드 + EXAMPLE(코드가 결정론 합성) → Neo4j(test DB)
  → 소비자: 아키텍트가 그래프에서 함수-규칙-예시-테이블-호출을 읽는다
```

**KV 캐시 규칙(중요 — 2026-08-06 정정)**: 접두사 재사용은 앞에서부터 일치하는 만큼만 된다.
따라서 **불변(고정 계약)은 맨 앞, 변동(대상·행 증거)은 맨 뒤**다. 이 순서는 테스트가 강제한다 —
`tests/pipeline/step7_analyze_code/test_semantic_generality_contract.py::test_each_rule_places_fixed_contract_before_variable_target_input`.
그리고 `llm/runners/prompt_rules.py`가 고정 절에 가변 placeholder가 들어오면 예외를 던져
이 계약을 코드로 강제한다.

**바이트 실측(K6 record 747콜 전수)**: system **532바이트 전 콜 동일**, user 앞 **2,070바이트
전 콜 공통**, `target_id: code:` 직후에서 처음 갈라짐. 공유 접두사 ≈ 2.6KB.

**KV 위반이 되는 것과 아닌 것**:
- 위반 O — 고정 절에 가변값을 넣기, 고정 절을 가변부 뒤로 옮기기.
- 위반 X — **고정 절의 내용을 바꾸기**. 바꿔도 전 콜이 같은 접두사를 공유하며 비용은
  run당 프리필 1회뿐이다.

**이전 판 정정**: 이 절의 옛 근거 "`hit_rate calls: 1316 · rate: 0.0%`"는 **틀렸다**. 그 지표는
`pipeline/execution/run_executor.py`의 **analyzer 자체 응답 캐시**이고 공식 cold는
`ROBO_LLM_RESPONSE_CACHE=false`로 끄고 돌므로 항상 0.0%다(계약을 안 건드린 K6 로그에도
`calls: 1314 · rate: 0.0%`). 서버 KV 재사용은 우리 쪽에서 측정 수단이 없다(08 §9 반증 등재와
일치). 이 정정이 중요한 이유: 옛 서술을 믿으면 지침 개편이 "캐시 때문에 불가"로 잘못 봉인된다.
**또한 "지침은 최소 토큰"은 오독이다(2026-08-07 사용자 확정)** — 최소화 대상은 입력의 노이즈와
출력의 중복이지 지침이 아니다. 지침은 공유 접두사라 길이 비용이 run당 1회이므로 필요한 만큼
디테일하게 쓴다.

## 8. 확인 불가·미검증

- **"저장소에 임시방편(해당 상황에서만 맞는 처리)이 없다"는 확인되지 않았다.**
  임시방편 여부는 코드의 생김새가 아니라 **의미**의 문제라 문자열·패턴 검색으로는 판별할 수 없다.
  이번에 돌린 `_runs/ast-contract-20260805/audit_hacks_repo.py`는 임시방편이 자주 남기는 **흔적**

  검출하지 못한다. 예를 들어 "조건이 여러 개일 때 첫 번째만 보는 처리", "현재 코퍼스에서 항상
