**Feature Branch**: `040-rules-node-gate`

**Created**: 2026-07-08 (갱신: 확정 설계 반영)

**Status**: ✅ 구현·검증 완료(2026-07-08, 9패스 실측 — 미커밋). 최종 진실 = [HANDOFF.md](./HANDOFF.md) **§0.8**:

프롬프트**(골격) + 골격 주석 스트립 + 커서 CodeNode. compact 결정지도 접근(§0.7)은 supersede — 요약 경유
= 전달게임 손실임을 LLM 입력로그로 실증, 규칙 증거를 원문(1차)으로 회귀.
**정확도(정답지 45결정): 엄격 58→78% / 부분 74→86%.** 만점 3파일, 게이트 4/4 회수, 죽은코드 환각 0.

ontology `rule_bearing` 제거.

**선행 스펙 관계**: 037·039(프롬프트로 과추출·환각 억제)를 **supersede**. 이 스펙은 (a) 구조적 원인을 **결정론 로직**으로 제거하고 (b) 프롬프트는 새 구조 전제로 단순화한다. 옛 스펙은 역사기록으로 보존.

## 핵심 전제 (왜 이 설계인가)

DBMS 규칙 품질 문제 중 **① 과소추출 · ② 커서 손실**의 뿌리는 프롬프트가 아니라 **파이프라인 구조**다 — 실측으로 확정(작업보고 §3). ③④는 지침·재료로 완화한다.

- **① 과소추출(구조)**: 규칙 입력이 **RAW(자식 서브트리 통째)** 라, 자식이 긴 문장(반복문 175줄)은 덩어리가 커서 AI가 결정을 **뭉갠다**. → 해결 = **긴 자식을 자식 요약으로 대체(compact)** = 덩어리 축소 → AI가 결정을 열거만 하면 됨.
- **② 커서 손실(구조)**: 커서(선별 조건 = 규칙 보유)가 **"선언"으로 분석에서 제외**돼 규칙이 아예 안 뽑힌다. → 해결 = 커서를 분석 대상(CodeNode)으로 포함.
- **③ 죽은 주석 환각(지침)**: compact 는 자식 내부의 죽은코드는 줄이나 **자기 줄·조상 골격의 주석은 남는다**(완전 차단 아님). → 프롬프트 상시 지침(공통 단계7 "주석처리 코드 = 무시")에 맡기고 잔여 오분류는 허용.
- **④ 값 매핑 소실(재료+지침)**: compact 가 자식 요약의 값 매핑(예: Q=평균/S·D=합산)을 지도에 노출 + 프롬프트가 매핑 보존을 지시.

→ ①② 는 **구조를 고쳐** AI가 열거만 하면 되게 한다. ③④ 는 지침·재료가 돕되 완벽을 강제하지 않는다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — 반복문·복합 문장에서 결정을 하나도 빠짐없이 뽑는다 (Priority: P1)

루틴의 톱레벨 문장(레벨1)을 규칙 추출에 넣을 때, **RAW 원문 통째가 아니라 "자식 요약으로 이뤄진 결정 지도(compact)"** 를 준다. 반복문·다중 DML 블록처럼 한 문장이 **여러 독립 결정**을 담으면, **결정마다 규칙 하나**가 나온다.

**Why P1**: 과소추출의 구조적 원인 제거. 결정은 이미 자식 요약에 존재(실측) — 지도로 주면 AI는 **열거만** 하면 되므로 거대·중첩 문장에서도 뭉개지 않는다. 거대 프로시저 크기도 안전.

**Independent Test**: `MINUTE_2` 재분석 → LOOP 규칙이 1개에서 정답지 커버 수준(적산차 재계산 + 일데이터 생성 등)으로 증가, 정답지 대비 누락 0.

**Acceptance Scenarios**:
1. **Given** 반복문 안에 적산차 재계산·일데이터 생성 등 독립 결정이 여러 개, **When** 규칙 추출, **Then** 각 결정이 별도 규칙으로 나오고 어느 것도 누락되지 않는다.
2. **Given** 단일 결정 문장(IF 트리 등), **When** 규칙 추출, **Then** 지금처럼 결정 하나로 유지된다(무회귀).
3. **Given** 1000줄+ 거대 프로시저, **When** 규칙 추출, **Then** compact 입력이라 토큰 폭주 없이 처리된다.

### User Story 2 — 커서(cursor)의 검증 규칙을 살린다 (Priority: P1)

커서 정의(쿼리 로직 보유 — 예: 불일치 데이터만 선별)를 **분석 대상 톱레벨 문장으로 포함**한다. 커서는 자기 요약·규칙을 **자기 노드**에 갖는다. 별도 인라인·짝짓기·순서 제어는 필요 없다.

**Why P1**: 커서가 "선언"으로 제외돼 검증 규칙이 **완전 손실**(실측: 커서 노드 5개 전부 요약 0). "특수처리 추가"가 아니라 **잘못된 제외를 제거**하는 것이라 로직이 더 깨끗해진다.

**Independent Test**: `MINUTE_2`·`DATA_ANALYSYS` 재분석 → 커서 노드에 "불일치인 것만 선별" 검증 규칙이 등장.

**Acceptance Scenarios**:
1. **Given** 검증 로직을 담은 커서 정의, **When** 분석, **Then** 커서 노드가 요약·규칙을 받는다.
2. **Given** 단순 조회 커서(로직 없음), **When** 분석, **Then** 규칙 0(빈 배열)이 정답 — 게이트는 기회를 줄 뿐 강제하지 않는다.
3. **Given** 커서와 그것을 쓰는 반복문, **When** 분석, **Then** 둘은 독립 분석되며 서로의 요약을 기다리지 않는다(타이밍 의존 0).

---

### User Story 3 — 요약을 조여 "결정 지도"를 깨끗하게 (Priority: P2)

노드 요약에서 **필수(도메인 값·상태코드·"어느 테이블에 무슨 작업")와 `[핵심]` 한 줄(UI 표시용)** 은 유지하되, **노이즈(커밋·롤백·예외 반복, 코드 토큰, 장황한 산문)** 는 제거한다.

**Why P2**: (주목적) 요약이 요약답지 않게 너무 길다(최대 860자, 커밋/롤백/코드토큰 노이즈). (연동) US1 compact 가 이 요약을 결정 지도 재료로 쓰므로, 요약이 지저분하면 지도도 흐려진다 — 요약 조이기는 compact 와 **한 세트**. 요약은 "무슨 작업을 했나"만 정확·간결히.

**Independent Test**: 재분석 후 요약 길이 분포가 감소(현행 최대 860자·200자 초과 107개 대비)하면서, 값 매핑(예: Q=평균/S·D=합산)은 요약에 보존.

**Acceptance Scenarios**:
1. **Given** 커밋/롤백/예외 서술이 반복되는 긴 요약, **When** 재분석, **Then** 그 기술 노이즈가 제거된다.
2. **Given** 값 매핑을 담은 집계 문장, **When** 재분석, **Then** 요약에 값 매핑이 남는다.
3. **Given** 임의 노드, **When** 요약 확인, **Then** `[핵심]` 한 줄이 보존된다(UI 계약).

### Edge Cases

- **결정 없는 데이터 노드**(순수 조회 SELECT): compact 지도라도 규칙 0(빈 배열)이 정답.
- **죽은 코드(주석)**: compact 는 자식 내부 죽은코드만 요약으로 줄인다. 자기 줄·조상 골격의 주석은 원문으로 남으므로 **완전 차단 아님** → 프롬프트 상시 지침(공통 단계7 "주석처리 코드 = 무시")에 맡기고 잔여 오분류 허용.
- **커서 다중 사용/미사용**: 커서는 자기 규칙을 자기 노드에 가지므로 사용처와 독립.
- **요약이 아직 빈 자식**: bottom-up 라운드로 자식이 먼저 분석되므로, 부모 compact 시점엔 자식 요약이 채워져 있다(기존 결정론 순서 유지).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 규칙 추출(rules_examples)의 입력 본문은 **compact(자식 구간 → 자식 요약 치환)** 여야 한다. RAW 원문 통째(재슬라이스) 금지. (즉 `batch_analyze` 의 규칙 분할이 `raw_body=True` 를 쓰지 않는다.)
- **FR-002**: 커서 정의(쿼리 로직 보유 노드)는 **분석 대상**(요약·규칙 추출 대상)에 포함되어야 한다. 단순 변수 선언과 구분한다.
- **FR-003**: 규칙 추출 프롬프트는 **"한 문장에 독립 결정이 N개면 규칙 N개"** 를 지시하고, **"완결된 문장 하나 = 규칙 하나"류 프레이밍을 제거**해야 한다. 반복문·다중 작업 블록에서 규칙 다수 산출을 정상으로 명시한다.
- **FR-004**: 규칙 추출 프롬프트는 **잔심부름(순수 조회·형변환·로그·커밋·롤백)을 규칙에서 제외**하고, "무폭주"의 의미를 "같은 결정 중복 금지"(규칙 수 축소 아님)로 명확히 해야 한다.
- **FR-005**: 노드 요약은 **`[핵심]` 한 줄(UI용)·도메인 값·상태코드·테이블 R/W·집계 매핑을 유지**하되, **기술 노이즈(커밋/롤백/예외 반복)·코드 토큰·장황한 산문을 제거**해야 한다. *(요약 프롬프트는 spec 029 WIP 와 겹침 — 조율 필요.)*
- **FR-006**: 시스템은 죽은(주석) 코드를 규칙·example 에 반영해서는 안 된다(활성 코드만 근거).
- **FR-007**: 재작성된 지침·예시는 **범용**이어야 한다(특정 프로젝트 식별자 0, 표준 SQL/도메인 관용구만).
- **FR-008**: 규칙 추출·요약 지침의 3분할 공통 system 은 분할 간 **글자단위 동일**(KV 캐시 prefix)해야 한다.
- **FR-009**: 게이트·재료 구성·커서 포함·요약 구조는 **순수 결정론**(LLM 0)이어야 한다.
- **FR-010**: Framework 전략은 이 변경의 영향을 받지 않아야 한다(무회귀).

### Key Entities *(include if feature involves data)*

- **코드 노드(CodeNode)**: 분석 단위. antlr type(라벨), 부모/자식 관계, 요약/규칙/테이블인사이트를 가짐.
- **결정 지도(compact body)**: 부모 문장 본문에서 자식 구간을 `[범위] 자식요약` 으로 치환한 입력 — 규칙 추출의 재료.
- **커서 정의(cursor)**: 쿼리 로직을 담은 노드. 분석 대상(요약·규칙)으로 승격.
- **노드 요약(summary)**: `[핵심]` 한 줄 + 도메인 값·작업. compact 의 구성 요소.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: `MINUTE_2` 재분석 시 반복문 규칙이 현행 1개에서 **정답지의 결정(적산차 재계산·일데이터 생성 등)을 누락 0** 으로 커버한다.
- **SC-002**: 커서의 검증 규칙(불일치 선별 등)이 재분석 후 그래프에 **등장**한다(현행 0 → 존재).
- **SC-003**: 죽은코드('대수평균' 등 주석 속 수식·값)를 근거로 한 규칙·예시를 **프롬프트 지침으로 억제**한다(공통 단계7). 잔여 오분류는 소수 허용(완전 0 강제 X — 완전 자동구분 불가).
- **SC-004**: 선행 개선(DECODE 값→결과 매핑 Q=평균/S·D=합산, fetch silent-pass, op 방향)이 재분석 후 **유지**된다(회귀 0).
- **SC-005**: 노드 요약 길이 분포가 감소(현행 최대 860자·200자 초과 107개 대비)하면서 값 매핑은 **보존**된다.
- **SC-006**: Framework(zapamcom) 재분석 규칙 분포가 변경 전과 **동일**하다(무영향).
- **SC-007**: 규칙·요약 지침에 프로젝트 특정 식별자 **0**, 동일 주제 중복 위치 **0**.

## Assumptions

- AST는 antlr가 이미 생성(주석은 AST 제외), 재분석 시 재파싱 불필요.
- 검증 정답 대상 = zapamcom(FW, DB `neo4j`), RWIS(DBMS, DB `test`).
- 자식 요약이 값·결정을 담는다는 전제(FR-005 요약 조이기가 이를 유지) 하에 compact 가 완전성을 지킨다 — 재분석 원문 대조로 재검증.
- 사내 LLM·Neo4j 가용(재분석 검증 가능).
