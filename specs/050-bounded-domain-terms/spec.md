# Spec 050 — bounded structured domain terms

## Problem

`code_summary`가 `domain_terms`를 `용어=뜻; ...` 문자열로 생성하면서 동일 항목을 반복해
30,000 토큰까지 소진할 수 있다. 구분자 기반 파싱은 용어나 뜻에 `;`, `=`가 포함될 때
깨지며, 단순 선착순 절단은 결제망 같은 검색 브리지 용어를 버릴 수 있다.

## Contract

- LLM 응답은 `domain_terms: [{term, meaning}, ...]`이며 허용 개수는 **0~10개**다.
  **10개는 목표가 아니라 절대 상한(마지노선)**이다. 후보가 없으면 `[]`, 6개면 6개가 정답이다.
- 정상 후보가 11개 이상이면 의미 우선순위 상위 10개만 선택하고 10번째에서 배열을 닫는다.
  11번째 항목은 출력·저장하지 않는다. 같은 우선순위에서는 원문에 먼저 등장한 후보를 우선한다.
- 현업 사전의 독립 표제어가 되는 업무어·약어, 외부 시스템/망/
  프로토콜, 이름 붙은 상태·정책처럼 검색 브리지가 되는 항목만 고른다.
- 변수·함수·상수·테이블·물리 컬럼 이름의 번역은 용어가 아니며 결정론 필터에서도 제외한다.
- 표제어는 해당 노드의 코드/주석에 정확히 존재해야 한다. 중복·빈 값·근거 없는 항목은
  결정론적으로 제거하고 이유와 개수를 로그로 남긴다.
- 애플리케이션 내부 표현은 `dict[str, str]`이다.
- Neo4j에는 중첩 map 대신 정규 JSON object 문자열을 `domain_terms_json` 속성으로 저장한다.
  재종합은 이를 엄격히 역직렬화하며 옛 세미콜론 문자열을 추측 파싱하지 않는다.
- framework와 DBMS 경로가 같은 계약을 사용한다.
- `code_summary` 출력 토큰에도 규칙별 상한을 둬 스키마 밖 폭주 시간을 제한한다.

## Acceptance

1. 0개와 10개 응답은 성공하고, 11개 응답은 Framework·DBMS 스키마와 정규화/저장 경계에서
   거부된다. 후보가 11개 이상일 때 프롬프트는 우선순위 상위 10개만 출력하도록 지시한다.
2. `;`와 `=`가 뜻에 포함돼도 저장/복원 결과가 동일하다.
3. 중복 또는 원문에 없는 표제어는 조용히 통과하지 않는다.
4. glossary 수집과 resynthesis는 구조화 계약만 소비한다.
5. 10개를 채우지 않는 정상 예시, 11개 이상에서 상위 10개만 고르는 경계 예시, 기존 표제어를
   `상세`·`코드`·`메시지`로 연쇄 파생하는 실패 예시를 두 전략 프롬프트에 함께 명시한다.
6. 실제 회귀에서 코드/주석에 `SK-VAN`이 있고 결제망 검색 브리지로 가치가 있다면,
   무의미한 기술 항목보다 우선되어야 한다.

이 명세는 specs 042/043의 `domain_terms` 평문 전송·저장 부분만 대체한다.
