# Feature Specification: 용어사전 품질 근본재설계 (추출 규칙 + AI 종합 + 조각 저장)

**Feature Branch**: `main` (spec dir: `043-glossary-quality-redesign`)

**Created**: 2026-07-10

**Status**: Draft

**Input**: User description: "용어사전 품질 근본재설계 — 추출 규칙 개정(주석 포함 실재 토큰) + AI 종합 단계(변종 통합·뜻 검증) + domain_terms 노드 저장. SK-VAN 사례로 실측된 설계 결함: 표제어 자격이 식별자 6종으로 제한되어 주석에만 있는 도메인 약어가 구조적으로 추출 불가 / 병합이 문자열 완전일치뿐이라 표기 변종이 영원히 안 묶이고 표본 1개짜리 오추출 뜻에 교정 기회가 없음 / build_glossary_step이 summarize_module_step과 병렬이라 모듈 요약을 참고할 수 없음 / domain_terms 조각이 그래프에 저장되지 않아 재종합에 전량 재분석이 필요."

## 배경 — 실측된 결함 사슬 (2026-07-10 세션)

레거시 코드 검색에서 현장 질의("우리 결제망에 연동하는 부분")가 정답 노드(요약이 "SK-VAN
원장 등록 여부 조회")에 도달하려면 용어사전이 다리를 놓아야 한다. 실측 결과 다리가 끊긴
지점은 GPU 모델 성능이 아니라 설계 4곳이었다:

1. **추출 규칙**: 표제어 자격이 "변수명·함수명·테이블명·컬럼명·상수명·문자열 리터럴" 6종으로
   제한 + "본문 주석 무시" → 주석에만 등장(24곳)하는 `SK-VAN`은 구조적으로 추출 불가.
   변종 `SKVAN`은 규칙 자기모순(Ctrl+F 판정법 vs 6종 열거) 틈으로 새어 나오며, 근거 사용이
   금지된 상태라 뜻을 지어냄("SK브로드밴드 통신망" — 인접 주석의 SKB에 오염).
2. **병합**: `term.lower()` 문자열 완전일치 → `SKVAN`/`SK-VAN`/`skvrq_yn`/`gc_skvan_bank_yn`
   이 영원히 별개 항목. 표본 1개짜리 오추출 뜻이 교정될 기회가 0.
3. **파이프라인 순서**: build_glossary_step이 summarize_module_step과 병렬 → 모듈 요약을
   원리상 참고 불가. 실측: 함수 주석만으로는 질의↔용어 임베딩 유사도 94위, 모듈 요약+형제
   용어를 재료에 더하면 6위(107개 중, 골드 토큰 미주입 검증).
4. **조각 유실**: 함수별 domain_terms 조각이 그래프에 저장되지 않음 → 종합을 다시 하려면
   전량 재분석(12분+)이 유일한 수단.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 도메인 약어가 표기 변종과 함께 한 항목으로 검색 재료가 된다 (Priority: P1)

레거시 코드를 모르는 사용자가 업계 통칭("결제망", "전자문서 교환")으로 질의하면, 코드가
그 실체를 어떤 표기(하이픈 유무·변수명·플래그명)로 부르든 용어사전의 **한 항목**이 그 실체를
대표하고, 뜻은 코퍼스 근거(주석·요약)에 기반해 그 실체의 역할을 서술한다.

**Why this priority**: 사전이 존재하는 이유 자체. 변종이 흩어지고 뜻이 오염되면 검색·번역·
임베딩 전 경로가 오도된다(실측: 오염 뜻이 번역 AI의 올바른 세상지식까지 눌러버림).

**Independent Test**: SKT 그래프 재분석 후 GLOSSARY 노드를 열어, 동일 실체의 표기 변종들이
한 그룹(대표 표기 + aliases)으로 묶였고 뜻에 오추출 정체 서술이 없는지 눈으로 대조.

**Acceptance Scenarios**:

1. **Given** 주석에만 등장하는 도메인 약어(예: 하이픈 표기 시스템명)가 있는 코퍼스,
   **When** 전량 분석 후 사전을 조회하면, **Then** 그 약어가 표제어로 존재한다.
2. **Given** 같은 실체를 가리키는 표기 변종이 여러 함수에 흩어진 코퍼스,
   **When** 사전 종합이 끝나면, **Then** 변종들이 한 항목의 aliases 로 묶여 있다.
3. **Given** 코퍼스 어디에도 그 약어의 정체(무슨 약자인지)가 안 적혀 있음,
   **When** 뜻이 생성되면, **Then** 뜻은 역할 서술만 담고 지어낸 정체 서술이 없다.

---

### User Story 2 - 규칙 완화 후에도 분석이 폭주 없이 완주한다 (Priority: P1)

표제어 자격을 주석 토큰까지 넓혀도, 과거 사고(단일 호출 30,000토큰·255초 무한반복·노드
유실)를 막은 방어(실재 토큰 유한성·조합어 창작 금지·축소 폴백)가 그대로 작동한다.

**Why this priority**: 규칙 완화는 폭주 방어를 건드리는 일. 이 회귀가 나면 P1 가치가
무의미(분석 자체가 죽음).

**Independent Test**: 양 코퍼스 전량 재분석 로그에서 폭주 지표 0건 확인.

**Acceptance Scenarios**:

1. **Given** 개정된 추출 규칙, **When** SKT·쇼핑몰 전량 재분석, **Then**
   `search_field_overflow` 0건, 노드 유실 0건.

---

### User Story 3 - 사전 종합을 재분석 없이 다시 돌릴 수 있다 (Priority: P2)

종합 프롬프트나 병합 로직을 개선했을 때, 12분짜리 전량 재분석 없이 저장된 조각으로
종합 단계만 재실행할 수 있다.

**Why this priority**: 종합은 반복 개선이 예정된 부분(뜻 품질·그룹 정확도). 재실행
비용이 12분이면 개선 루프가 죽는다.

**Independent Test**: 그래프에서 노드별 domain_terms 조각을 조회해 종합 입력을 재구성.

**Acceptance Scenarios**:

1. **Given** 전량 분석이 끝난 그래프, **When** 노드를 조회하면, **Then** 각 코드 노드에
   domain_terms 조각이 속성으로 저장되어 있다.

---

### Edge Cases

- 용어가 등장하는 노드가 매우 많으면(공통 상수 등)? → 종합 입력은 노드 문맥 상한(개수 컷)을
  두되, 컷이 있었음을 로그로 남긴다(조용한 절단 금지).
- 종합 AI 콜이 실패하거나 근거 인용이 없으면? → 그 용어는 수집된 조각 그대로 유지(악화 금지,
  제거 전용 아님 — 종합은 개선 전용).
- aliases 지목이 서로 어긋나면(A→B 는 지목, B→A 는 아님)? → 결정론 합집합(union)으로 묶되,
  지목 근거가 인용된 경우만 인정.
- 표제어가 하나도 안 나오는 함수? → 기존과 동일하게 빈 문자열(변화 없음).
- 모듈 요약이 없는 노드(모듈 미소속)? → 그 노드의 summary·search_text 만으로 종합(모듈
  요약은 부가 재료).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001 (표제어 자격 개정)**: 분석 단계의 용어 추출은 표제어 자격을 "그 함수 텍스트
  (주석 포함)에 글자 그대로 실재하는 토큰"으로 정의해야 한다. 식별자 6종 열거 제한과
  "주석 무시" 지시는 용어 추출 필드에서 제거된다. 폭주 방어 — ⓐ 실재 토큰만(Ctrl+F 판정,
  후보 유한) ⓑ 조합어·변형 창작 금지 ⓒ 실패 시 축소 폴백 — 는 문구 그대로 유지된다.
- **FR-002 (뜻 근거주의)**: 용어의 뜻은 그 함수 텍스트에 실제로 적힌 표현(주석 포함)을
  1차 근거로 작성해야 한다. 동작 서술(신규/갱신 등)은 결정론 매핑(codebase_notes)이 주석과
  어긋나면 결정론이 우선한다(기존 0.2 원칙은 동작 서술로 한정해 유지). 실체의 정체(무슨
  약자·무슨 기관/회사)가 텍스트 어디에도 없으면 역할만 서술하고 정체를 창작하지 않는다.
- **FR-003 (조각 저장)**: 함수별 domain_terms 조각은 코드 노드 속성으로 그래프에 저장되어야
  한다(화면 비노출 유지). 저장된 조각만으로 종합 단계를 재실행할 수 있어야 한다.
- **FR-004 (AI 종합 단계)**: 사전 종합은 결정론 수집(현행 유지) 뒤 AI 종합을 수행해야 한다:
  용어당 1콜 병렬(분석에 쓰는 것과 같은 LLM 재사용), 전 용어 동일 처리(형태·표기 기반 선별
  필터 금지). 각 콜의 입력은 ⓐ 전체 용어 이름 목록(모든 콜에 공유되는 접두 — 캐시 친화)
  ⓑ 그 용어가 글자 그대로 실재하는 노드들의 summary·search_text(상한 있음, 컷 로그)
  ⓒ 그 노드들의 모듈 요약. 출력은 ⓐ 종합된 뜻(코퍼스 근거 인용 필수 — 인용 없으면 기존
  조각 유지) ⓑ 같은 실체를 가리키는 표기 변종 지목(aliases, 근거 인용 필수).
- **FR-005 (그룹 확정·저장)**: 변종 지목은 결정론 합집합으로 그룹을 확정하고, GLOSSARY
  노드에 대표 표기 + aliases + 종합 뜻으로 저장해야 한다. 검색기가 기존에 읽던 스키마
  (terms_json: canonical/colloquial/meaning)와 호환되어야 한다(aliases 는 colloquial 로 실림).
- **FR-006 (파이프라인 순서)**: 사전 종합은 모듈 요약 생성이 끝난 뒤 실행되어야 한다
  (현행: 병렬 그룹 동시 실행 → 변경: 모듈 요약 완료 후).
- **FR-007 (범용성 제약)**: 이 기능의 어떤 규칙·코드도 특정 토큰·특정 표기 형태(대문자
  정규식, 하이픈 처리, 특정 도메인 단어)를 겨냥해서는 안 된다. 판단이 필요한 곳(변종 묶기·
  뜻 종합)은 AI 가, 기계적인 곳(수집·합집합·저장)은 결정론 코드가 맡는다.
- **FR-008 (측정무결성)**: 프롬프트의 예시는 평가 코퍼스(SKT·쇼핑몰)에 실재하는 용어·
  테이블·시나리오를 포함해서는 안 된다(무관 도메인 예시만).

### Key Entities

- **용어 조각(domain_terms)**: 함수 1개가 낳은 "표제어=뜻; …" 문자열. 코드 노드 속성으로
  저장. 종합의 원재료.
- **용어 그룹**: 같은 실체를 가리키는 표기 변종의 묶음. 대표 표기(canonical) + 변종
  (aliases=colloquial) + 종합 뜻(meaning). GLOSSARY 노드 terms_json 에 저장.
- **종합 문맥 묶음**: 용어 1개의 AI 종합 입력 — 전체 용어 이름 목록(공유 접두) + 등장 노드
  요약들 + 모듈 요약.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001 (변종 통합)**: SKT 그래프 전량 재분석 후, 동일 실체의 표기 변종(하이픈 유무·
  전역변수·플래그 표기)이 사전에서 한 항목으로 묶여 있고, 뜻이 코퍼스 근거 기반이다
  (지어낸 정체 서술 0건 — 사전 전수 눈 대조).
- **SC-002 (폭주 0)**: 양 코퍼스 전량 재분석에서 폭주 지표(search_field_overflow) 0건,
  분석 노드 유실 0건.
- **SC-003 (게이트)**: 위험질의 게이트가 검색기 쪽 해피패스 규칙 0인 상태에서 기준을
  넘는다 — SKT ≥ 6/7, 쇼핑몰 ≥ 9/11 (같은 그래프 위 비교).
- **SC-004 (소음 무증가)**: 사전의 일반어·숫자 표제어·조합 창작 표제어가 현행 대비 늘지
  않는다(재분석 후 전수 검사, 현행 기준: 조합어 0·숫자 표제어 0).
- **SC-005 (재종합 가능)**: 재분석 없이 저장된 조각만으로 종합 단계를 재실행해 같은 스키마의
  사전이 나온다.

## Assumptions

- 분석용 LLM(사내 GPU)은 근거가 입력에 주어지면 종합·요약을 신뢰할 수준으로 수행한다
  (실측: summary·모듈 요약 품질 정상 — 고장난 건 근거 사용이 금지됐던 용어 필드뿐).
- 종합 단계 비용은 용어 수에 비례(SKT 107콜·쇼핑몰 463콜, 병렬)하며 분석 본체(549콜)
  대비 오차 수준이다(용어당 문맥 ~800토큰 실측).
- 검색기 쪽 의미대조(임베딩) 활성화·임계는 이 스펙 범위 밖 — 새 사전 생성 후 놀이터에서
  실측으로 별도 결정한다.
- 기존 그래프(현 SKT·쇼핑몰)는 재분석 전까지 기존 사전으로 동작한다(스키마 호환 유지).
