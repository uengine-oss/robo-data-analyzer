# Feature Specification: 전역 앵커와 1홉 근거 검색

**Status**: In progress
**Input**: 의미검색이 질의 변형마다 최대 12개 core를 고른 뒤 각각 확장하여 한 질의에 38개 코드가 평면 반환되는 문제를, 과거 골드 리콜을 훼손하지 않고 줄인다.

## 목표

- 원문·약어 병기·안전한 재작성은 후보를 넓히는 책임만 갖는다.
- 모든 변형 후보를 합친 뒤 한 번의 전역 선별로 주요 앵커 3개를 고른다.
- 앵커에 실제로 연결된 1홉 코드와 TABLE은 `evidence`로 분리한다.
- 기존 방식과 새 방식을 같은 53개 골드로 A/B 측정하기 전에는 기존 경로를 제거하지 않는다.

## 요구사항

- **FR-001**: 각 질의 변형은 독립적인 최종 cluster를 만들지 않고 후보 ID와 리콜 순위만 제공해야 한다.
- **FR-002**: 중복 후보는 ID로 병합하고, 원문과 채택된 보강 질의를 함께 사용해 전역 의미 점수를 계산해야 한다.
- **FR-003**: 최종 주요 앵커는 기본 3개이며 결과에서 `role=anchor`로 구분해야 한다.
- **FR-004**: 근거 확장은 정확히 1홉이어야 하며 CALLS 양방향과 READS/WRITES/AFFECTS_TABLE을 사용해야 한다.
- **FR-005**: TABLE은 검색 앵커가 아니어도 실제 그래프 노드로 결과에 포함되어야 한다.
- **FR-006**: evidence는 어떤 앵커와 어떤 관계로 연결됐는지 구조화된 근거를 포함해야 한다.
- **FR-007**: hub 및 의미 게이트 정책은 기존 검색과 동일한 설정을 재사용해야 한다.
- **FR-008**: `legacy` 모드를 보존해 동일 DB·동일 골드에서 회귀를 직접 비교할 수 있어야 한다.
- **FR-009**: 평가기는 전체 recall뿐 아니라 anchor recall, evidence 구조 구제, 결과 크기를 각각 보고해야 한다.
- **FR-010**: 새 방식은 기존 full-gold 회수율보다 낮으면 기본값으로 채택하면 안 된다.

## 비기능 요구사항

- 검색 로직에 쇼핑몰·SKT 함수명이나 테이블명을 하드코딩하지 않는다.
- 그래프는 읽기 전용이다.
- 기존 실행 중인 분석 서버는 구현 도중 재시작하지 않는다.
- 점수는 정답 확률로 해석하지 않는다.

## 성공 기준

- 53개 골드 A/B 결과가 질의별로 기록된다.
- 새 방식의 full-gold recall이 legacy보다 낮지 않다.
- 평균 및 최대 반환 노드 수가 legacy보다 감소한다.
- 대표 복합 질의에서 anchor와 evidence가 구분되고 TABLE 근거가 반환된다.
