# 084 — 에이전트 제출 도구 미호출 복구

작성: 2026-07-23. 근거: run14·15·16 이 **모두 스캔 에이전트에서 즉사**했다.

## 원인 (실측으로 확정)

에이전트 2번째 턴에서 모델이 도구 호출 대신 평문 20토큰
(`[Candidate: proframe-c-pfm-dbio — C files, DBIO macro likely]`)을 냈고, LangChain
agent 루프는 도구 호출이 없으면 그대로 종료하므로 `StructuredResponseMissingError` 로
run 전체가 죽었다.

같은 입력 9,176 토큰에서 run13 은 도구 호출(출력 290토큰)을, run14~16 은 평문
(출력 20토큰)을 냈다. 탐욕 디코딩(temperature 0.1·top_k 1)인데도 출력이 갈렸으므로
서버측 배치 비결정성(사건 G)이며, **스트리밍 킬스위치를 끄고도 동일하게 실패**해
spec 080/082/083 변경과 무관함을 실측으로 배제했다.

즉 결함은 모델의 흔들림 자체가 아니라 **한 턴의 흔들림이 12분짜리 run 전체를 죽이는
복구 부재**다.

## 계약 (변경 후)

- `run_structured_agent` 는 제출 도구 없이 끝난 invoke 를 **총 3회까지** 시도한다
  (최초 1회 + 재시도 2회, `_MAX_SUBMIT_ATTEMPTS`).
- 재시도는 앞선 대화를 그대로 이어받고 **고정 문구** `_SUBMIT_NUDGE` 한 줄만 덧붙인다
  ("관찰한 것만으로 제출하라 / 메모 쓰지 말고 도구를 한 번 호출하라 / 못 본 항목은 비워라").
  문구가 고정이라 재현성을 깨지 않으며, 샘플링 파라미터는 손대지 않는다.
- 재시도는 `submit_tool_missing` 경고로 매번 표면화한다(조용한 복구 금지).
- 총 LLM 호출량은 기존 `max_calls` 미들웨어가 그대로 막는다.
- 3회 모두 실패하면 종전처럼 `StructuredResponseMissingError` 로 크게 실패한다.
