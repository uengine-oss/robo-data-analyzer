# Feature Specification: 테이블·컬럼 분석설명 유실 복구 + 식별자 빈값 정규화

**Feature Branch**: `024-analyzed-description-recovery`

**Created**: 2026-06-26

**Status**: Draft

**Input**: User description: "테이블·컬럼 분석설명(analyzed_description) 조용한 유실 수정 + 노드 식별자(FQN/id) 빈값 정규화. step7 쓰기가 노드 id로 MATCH 하는데 step6 FQN 형식과 그래프 노드 정식 id 형식(db 빈값 선두 점)이 불일치 → 조용히 no-op 유실. 빈값 저장(빈값미저장 위반)·무경고 no-op 도 동반 결함."

## 배경 (실측 — logs/analysis.run/latest/analyzer.log + 그래프 직접조회)

LLM이 생성한 **테이블·컬럼 분석설명이 그래프에 저장되지 않고 조용히 사라진다**.
- **실측 채움률**: TABLE.analyzed_description 6/16, COLUMN.analyzed_description 61/153. 가장 많이 참조되는 RDD01DD_TB(쓰기16·읽기17=33접근)도 빈 채.
- **근본원인**: 노드 정식 식별자 = `{db}.{schema}.{name}`. 이 데이터(오라클)는 db가 없어 빈값 → 선두 점이 남은 `.RWIS.RDD01DD_TB`. 그런데 분석 단계가 만든 테이블 참조 FQN은 빈 db를 빼서 `RWIS.RDD01DD_TB`. 분석설명을 **식별자로 매칭해 저장**하는데 두 형식이 달라 **매칭 0건 → 아무 노드도 갱신 안 됨(조용한 no-op)**. 우연히 두 형식 다 처리된 6개 테이블만 생존.
- **동반 결함**: ① 식별자가 빈 구성요소(db)일 때 **선두 점을 남김**(불일치의 뿌리). ② 테이블·컬럼 저장이 "빈값 미저장" 정책(spec 020)을 우회해 **빈 db·빈 comment를 키로 저장**. ③ 매칭 0건 갱신이 **경고 없이 통과**해 유실이 드러나지 않음.

이 기능은 (1) 유실된 분석설명을 복구하고, (2) 식별자 형식을 단일 진실로 정규화하며, (3) 빈값 저장·조용한 유실을 근본 차단한다. 헌법 — 빈값미저장·근본수정·조용한실패 표면화·전략무관 준수.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 모든 테이블·컬럼이 분석설명을 갖는다 (Priority: P1)

분석을 마치면, 코드가 실제로 사용하는 모든 테이블과 컬럼은 LLM이 생성한 분석설명(역할·의미)을 그래프에 보유한다. 사용자가 검색·시각화·문서에서 어떤 테이블을 봐도 "이 테이블이 뭐 하는지" 설명이 비어 있지 않다.

**Why this priority**: 유실의 직접 해소. 분석설명은 검색 품질·이해도의 핵심 자산인데 가장 많이 쓰는 테이블이 비어 있다. 데이터 무결성 최우선.

**Independent Test**: 재분석 후 그래프에서 "코드가 R/W하는 테이블·컬럼 중 분석설명이 빈 것"이 0인지 확인. 특히 RDD01DD_TB가 채워졌는지.

**Acceptance Scenarios**:

1. **Given** 코드가 참조하는 테이블/컬럼, **When** 분석 완료, **Then** 그 테이블·컬럼에 분석설명이 저장되어 있다(생성됐는데 유실되는 경우 0).
2. **Given** LLM이 분석설명을 정상 생성, **When** 저장, **Then** 생성된 설명이 반드시 해당 노드에 반영된다(매칭 실패로 사라지지 않는다).
3. **Given** 가장 많이 참조되는 테이블(RDD01DD_TB), **When** 분석, **Then** 분석설명이 비어 있지 않다.

### User Story 2 - 노드 식별자 형식이 단일 진실로 일치 (Priority: P1)

노드를 만드는 쪽과 그 노드를 참조·갱신하는 쪽이 **동일한 식별자 형식**을 쓴다. 식별자에 빈 구성요소가 있으면 그 부분은 구분점 없이 생략되어, 어디서 만들든 같은 키가 나온다.

**Why this priority**: US1 유실의 근본 원인. 식별자가 한 형식으로 통일되지 않으면 분석설명뿐 아니라 미래의 어떤 후처리 갱신도 같은 방식으로 샐 수 있다.

**Independent Test**: 빈 db 환경에서 노드 생성 식별자와 후처리 참조 식별자가 글자 단위로 동일한지. 선두 점(빈 구성요소)이 식별자에 없는지.

**Acceptance Scenarios**:

1. **Given** db가 없는 데이터(스키마만 존재), **When** 테이블·컬럼 노드 생성, **Then** 식별자는 빈 db를 점으로 남기지 않는다(`.RWIS.X`가 아니라 `RWIS.X`).
2. **Given** 같은 테이블을 가리키는 생성 시점과 후처리 시점, **When** 식별자 조립, **Then** 두 식별자가 동일하다.
3. **Given** db가 존재하는 데이터, **When** 식별자 조립, **Then** db를 포함한 완전 식별자가 일관되게 생성된다(전략무관).

### User Story 3 - 빈값 미저장 + 조용한 유실 표면화 (Priority: P2)

빈 값은 노드 속성으로 저장되지 않는다(있는 값만). 그리고 후처리 갱신이 어떤 노드에도 반영되지 못하면(매칭 0건) 조용히 넘어가지 않고 경고로 드러난다.

**Why this priority**: 클린성(빈값미저장 정책 일관) + 미래 유실 예방의 안전망. US1/US2가 이번 유실을 고치면, US3는 같은 유형의 유실이 다시 조용히 일어나지 않게 한다.

**Independent Test**: 빈 comment·빈 db가 키로 저장되지 않는지. 매칭 0건 갱신 시 경고 로그가 남는지.

**Acceptance Scenarios**:

1. **Given** 값이 빈 속성(빈 comment·빈 db), **When** 노드 저장, **Then** 그 속성은 키로 저장되지 않는다(빈값미저장 일관).
2. **Given** 후처리 갱신이 어떤 노드와도 매칭 안 됨, **When** 갱신 시도, **Then** 경고로 표면화된다(조용한 no-op 금지).

### Edge Cases

- db가 빈 데이터(오라클·단일 스키마): 식별자에 빈 db를 생략(점 안 남김). 가장 흔한 케이스.
- db가 있는 데이터(SQL Server류): 식별자에 db 포함. 형식이 구성요소 수에 따라 자연히 늘고 줌.
- 코드가 참조하지 않는 테이블(분석설명 입력 없음): 분석설명이 없는 게 정상(유실 아님) — 빈값미저장.
- 식별자를 위치로 파싱하는 소비처(점 개수 의존): 형식 변경 시 깨지지 않게 양끝 점검 필요(plan에서 전수조사).
- 이미 채워진 6개 테이블·기존 노드 식별: 정규화 후에도 깨지지 않아야(회귀 0).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 코드가 R/W하는 모든 테이블·컬럼은 분석설명이 생성되면 **그래프 해당 노드에 반드시 반영**되어야 한다(매칭 실패로 인한 유실 0).
- **FR-002**: 노드 식별자는 **단일 형식 규칙**으로 생성·참조되어야 하며, 노드를 만드는 쪽과 후처리로 참조·갱신하는 쪽이 **동일한 식별자**를 산출해야 한다.
- **FR-003**: 식별자의 **빈 구성요소(예: 빈 db)는 구분점 없이 생략**되어야 한다(선두/중복 점 금지). db가 존재하면 포함(전략무관).
- **FR-004**: 노드 속성 저장은 **빈값을 키로 저장하지 않아야** 한다(빈값미저장, spec 020 일관) — 테이블·컬럼 저장 포함.
- **FR-005**: 식별자로 매칭해 갱신하는 후처리가 **어떤 노드와도 매칭되지 않으면 경고로 표면화**해야 한다(조용한 no-op 금지).
- **FR-006**: 모든 변경은 **전략무관**(DBMS·framework 공통 식별자 규칙) — 특정 DB/스키마 가정·하드코딩 금지.
- **FR-007**: 변경 후 **재분석 실행으로 검증** — 코드가 쓰는 테이블·컬럼 분석설명 빈 것 0 + 기존 채워진 것·기존 노드 식별 회귀 0.

### Key Entities *(include if feature involves data)*

- **테이블/컬럼 노드**: 식별자(db·schema·name 합성) + 1차 설명(DDL) + **분석설명(LLM 합성)**. 분석설명이 후처리로 식별자 매칭되어 저장됨.
- **노드 식별자(FQN/id)**: 노드를 가리키는 단일 키. 구성요소(db/schema/name)로 합성. 빈 구성요소 생략 규칙 적용 대상.
- **분석설명 입력(table insights)**: 코드 분석이 만든 "이 테이블이 무슨 역할" 후보. 식별자 형식이 노드와 일치해야 저장됨.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 재분석 후, 코드가 R/W하는 테이블 중 분석설명이 빈 것 **0개**(현재 10/16 빈 것 → 0). 컬럼도 동일 기준으로 유실 0.
- **SC-002**: 가장 많이 참조되는 테이블(RDD01DD_TB)을 포함해 분석설명 보유.
- **SC-003**: 빈 db·빈 comment가 노드 속성 키로 **저장되지 않음**(빈값미저장 일관).
- **SC-004**: 노드 식별자에 **빈 구성요소로 인한 선두/중복 점 0개**.
- **SC-005**: 기존에 채워졌던 6개 테이블·기존 노드 식별이 **깨지지 않음**(회귀 0) — 재분석·소비처(검색·시각화) 정상.
- **SC-006**: 식별자 매칭 갱신이 0건일 때 **경고가 남음**(조용한 유실 재발 방지).

## Assumptions

- 분석설명 유실의 근본은 식별자 형식 불일치(빈 db 선두 점)이며, 로그·그래프 실측으로 확인됨.
- 측정 데이터는 RWIS(단일 오라클 스키마, db 빈값). db가 있는 환경·framework는 구조 일반화로 대비하되 실측 검증은 현 데이터로.
- 식별자 형식 변경의 영향 범위(소비처: 검색·시각화·타 서비스 Cypher·식별자 위치 파싱)는 plan 단계 전수조사로 확정한다.
- 노드 식별자 단일화(spec 017)·노드 속성 정합(spec 020)의 후속 — 그 규칙을 식별자 빈값·후처리 저장에 일관 적용한다.
