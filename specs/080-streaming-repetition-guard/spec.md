# 080 — 생성 중 반복 폭주 실시간 차단 (Streaming Repetition Guard)

작성: 2026-07-23. 근거: 딥리서치 2차(전면 재검토) 채택 항목 1 — 기존 3층 방어(구조
차단 > 출력 상한 > 품질 게이트)에 없는 "생성 중(during-generation) 감지" 층.
서버 네이티브 `no_repeat_ngram_size` 는 사내 sglang 빌드 미지원을 실측(500 오류)으로
확인 → 클라이언트 결정론 감지기로 구현한다.

## 목적

반복 폭주(사건 A·B·C 유형: 공백/문구 루프)가 룰별 max_tokens 상한(피해 수십~백여 초)에
닿기 전에 **스트리밍 수신 중 즉시 차단**해 피해를 초 단위로 줄인다. 산출물 계약은
불변 — 정상 응답은 바이트 하나 안 바뀐다.

## 계약

- 대상 경로: `run_yaml_rule` (yaml 룰 전 호출 — 사건 A·B·D 표면 + 최대 상한 20k 룰).
  에이전트 경로(상한 8k, 피해 ≤55초)는 이번 슬라이스 제외.
- 감지 규칙(결정론, 단일 규칙): 누적 출력의 **접미 창(window) W=3072자가 주기
  p ≤ 512 로 정확히(exact) 반복**되면 폭주로 판정한다. 판정은 회전 트릭
  `(s+s).find(s, 1)` 의 최소 주기로 하며, W/p ≥ 6 회 반복이 자동 보장된다.
  공백 폭주는 주기 1로 같은 규칙에 포함된다.
- 오탐 안전 논거: 정상 구조화 출력은 항목 간 내용이 달라 3,072자를 **정확히** 주기
  반복할 수 없다(구조 키 반복은 내용이 끼어 비주기). 3,072자 미만 출력은 검사 자체가
  시작되지 않는다(한줄요약 등 원천 면제).
- 발동 시: `RepetitionLoopAborted` raise → 스트림 종료(서버는 연결 종료로 요청 abort)
  → 기존 호출부 예외 처리로 흡수(부분 표시·회계 등식 유지·무중단 계속). 로그 이벤트
  `repetition_guard_abort` 로 greppable.
- 스트리밍 전환: `build_llm_client(streaming=True)` → ChatOpenAI `streaming=True,
  stream_usage=True`(usage 회계 유지 필수 — usage 소실 시 기존 UnmeteredLlmCallError
  가 크게 실패시켜 침묵 불가). 킬스위치 `ROBO_LLM_REPETITION_GUARD`(기본 ON).

   한국어 무발동 + 청크 경계 불변성. 기존 unittest 체계.
