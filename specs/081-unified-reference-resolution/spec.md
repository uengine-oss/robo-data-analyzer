# 081 — 코드↔외부 아티팩트 통합 참조 연결

> 근거 리서치: `specs/078-external-reference-simplification/research/deep-research-3-indirect-reference-architecture.md`,
> 동 `deep-research-4-db-procedure-file-references.md`.
> 사용자 확인 문서: `docs/작업보고내용/2026-07-23-코드-외부파일-참조연결-현황진단과-개선결론.md`.
> 078 은 종결됐고 이 spec 이 링킹 계약을 대체한다.

## 1. 목표

코드 단위(메서드/함수/프로시저)가 외부 아티팩트를 참조하면 그래프로 잇는다.
**의미 판단은 하지 않는다 — 잘 쪼개고 잘 연결하는 것이 전부다.**

## 2. 절대 계약

- **결정론만.** 리터럴로 확정될 때만 연결. LLM 은 이 경로에 관여하지 않는다.
- **틀린 연결 0 > recall.** 실측 FP 가 1건이라도 나오면 그 규칙만 즉시 비활성화하고 기록한다.
- **콜체인 추적 금지.** 값이 없는 지점(파라미터만 받는 함수)은 앵커가 아니다.
- 기존 연결(ofbiz 119 · ukesa 115 · swing 4 · 링킹 gold 8케이스)이 **하나도 줄지 않을 것.**

## 3. 구조 — 사전 + 사실의 조인

언어별 분기를 링킹 로직에 넣지 않는다. 양쪽이 각자 문자열을 내놓고 한 번 조인한다.

```
참조 대상 사전 (target_index)          코드 문자열 사실 (symbol_values + 본문 리터럴)
  chunk_key   조각 이름표                 · 루틴 본문의 따옴표 리터럴
  file_name   파일 이름                   · 상수를 폴딩해 얻은 확정 값
  file_path   경로 접미                   · (후속) 관용구 인자 — FOPEN/BULK INSERT/fopen
                       \        /
                        조회 1회
                           ↓
              exact → file(강등) → 미연결
```

언어마다 다른 것은 **"확정 문자열을 어떻게 뽑는가"** 뿐이며, 그것은 데이터(규칙표)로 외부화한다.

## 4. 참조 대상 사전 계약

| 종류 | 무엇 | 대상 노드 |
|---|---|---|
| `chunk_key` | `EXTERNAL_CHUNK.keys` | EXTERNAL_CHUNK |
| `file_name` | 파일 이름 (`.` 포함 필수) | PROJECT_FILE |
| `file_path` | 경로의 모든 접미 (`a/b/c.xml`, `b/c.xml`, `c.xml`) | PROJECT_FILE |

- `derived_document` 청크는 대상이 아니다(078 계약 유지).
- 자기 자신 파일로의 연결은 만들지 않는다.

## 5. 조회 알고리즘 (결정론)

입력 문자열 `v` (최대 240자):

1. **경로형**: `v` 에 `/` 또는 `\` 가 있으면 정규화(`\`→`/`, 선행 `./` 제거) 후 `file_path` 조회.
   유일하면 **파일 연결(exact)**. 복수면 미연결.
2. **토막 후보**: `v` 자체 + **키 문자셋 밖 문자 뒤에서 시작하는 접미들** 중
   `is_reference_key` 를 통과하는 것만, **긴 것부터** 순서대로.
   - 키 문자셋은 `span_common._KEY_PATTERN` 하나가 단일 진실이다. 프레임워크 지식을 쓰지 않는다.
   - **공백이 있는 값은 분해하지 않는다.** 식별자·경로에 공백은 없고, 공백이 있는 값은 사람이
     읽는 문장이다. 실측 근거는 §5-2.
3. 각 후보를 `chunk_key` → `file_name` 순으로 조회하고 **첫 성공에서 멈춘다**:
   - 청크 1개 → **조각 연결**
   - 청크 2개 이상 → **미연결** (더 짧은 후보로 내려가지 않는다)
   - 파일 이름 1개 → **파일 연결**

### 5-1. 롤백한 규칙 — 파일 강등 (실측 FP)

같은 파일 안에서 키가 겹치면 그 **파일**로 강등 연결하는 규칙을 넣었다가 **롤백했다.**

- **실측**: ofbiz-order-standalone 에서 강등 엣지 **127건** 발생. 내용은 `orderId`·`statusId`·
  `amount`·`quantity`·`partyId` 등 **흔한 필드명**이었고, 자바 5개 파일이 `entitymodel.xml`
  하나로 127개 엣지를 만들었다.
- **판정**: 흔한 단어의 우연한 일치는 참조가 아니다. 신호를 묻는 그래프 오염이며
  `FP 0 > recall` 위반이다.
- **조치**: 규칙 제거. 대상이 유일하지 않으면 **미연결**이 정답이다.
  `ReferTo.resolution` 속성도 함께 제거했다(강등이 없으면 구분할 값이 없으므로 죽은 스키마).
- **비용**: loan-ejb-app 의 세션 7건은 같은 XML 안에서 정의·언급으로 키가 겹치므로
  **여전히 미연결**로 남는다. 엔티티 7건은 유일하므로 연결된다.

### 5-2. 좁힌 규칙 — 공백 있는 값은 분해 금지 (실측 FP)

- **실측**: ofbiz `OrderServices.java` 에서 오연결 **6건**. 리터럴 `" for order "` 를 다듬은
  `for order` 를 공백 경계로 잘라 끝 토막 `order` 가 엔티티 키 `order` 와 일치했다.
- **판정**: 문장 조각의 끝 단어는 참조가 아니다. FP.
- **조치**: 통째 롤백 대신 경계를 좁혔다 — **값에 공백이 있으면 구분자 분해를 하지 않는다.**
  식별자(`java:comp/env/ejb/X`)·경로(`%s/subscribers.dat`)에는 공백이 없다.
- **효과**: 오연결 6건 제거, 정상 연결 28건(별명 17 · 파일 11) 전부 유지.
  `tests/.../test_target_index.py` 로 고정.

### 5-4. 선행 결함 — 자바 AST 가 초기화식을 버리고 있었다 (antlr-code-parser)

`CONSTANT_FIELD`/`FIELD` 에 `initValue` 가 없어 `Constant.value` 가 항상 빈 값이었고, 이 spec 의
상수 폴딩이 전부 무효였다. C/PL/SQL/PostgreSQL/Python 리스너는 모두 방출하고 **자바만 누락**.
`JavaAstListener.enterFieldDeclaration` 에서 선언자가 1개일 때만 `initValue` 를 싣도록 수정.
바이트 골든은 자바 1개 노드에 `initValue` 필드만 추가됨을 필드 단위로 확인한 뒤 갱신(다른 4개
언어 골든 바이트 동일). 파서 테스트 107/107.
**부수효과**: 같은 코퍼스에서 `references` 7 → 745, `init_by` 0 → 15.

### 5-5. 미해결로 남긴 관측 (이 spec 범위 밖)

- `SKIP_DIRS` 에 `out` 이 있어 `data/out/` 같은 **송신 인터페이스 디렉터리가 통째로 미수집**된다
  (`in` 은 수집됨). 제품 전역 영향이라 임의 변경하지 않고 기록만 한다.
- 전체 파이프라인 실행에서 `link_residual_patterns_step` 이 `ModelCallLimitExceeded
  (residual, max_calls=15)` 로 1회 실패했다. 연결 단계와 무관한 LLM 보강 단계이며 인과 미확정.

## 6. 코드 문자열 사실 계약

- **본문 리터럴**: 주석/삼중따옴표 제외(기존 `key_index`).
- **상수 폴딩**: `a + b + …` 의 **모든 피연산자가 확정 문자열일 때만** 단일 값 산출.
  하나라도 비상수/미해결이면 **즉시 None**. 재귀 깊이 상한 4.
- **색인 범위**: 같은 owner 우선, 없으면 프로젝트 전역. 전역에서 **같은 이름이 서로 다른 값**을
  가지면 그 이름은 **폐기**(모호).
- **한정 참조** `Class.NAME` 인식. 마지막 마디로 조회한다.
- **불변 확인**: `Constant` 는 정의상 상수. `Variable` 은 `final/const/immutable` 표지가 있을 때만.
  루틴 본문에서 재대입되면 그 루틴에서는 사용하지 않는다(기존 규칙 유지).

## 7. 그래프 계약 변경

- **노드 타입 추가 0, 관계 타입 추가 0.**
- `REFER_TO` 의 대상이 `EXTERNAL_CHUNK` **또는** `PROJECT_FILE` 로 확장된다.
- `REFER_TO` 에 속성 **`resolution`** 추가: `"exact"` | `"file"`.
- 미해결 참조는 **그래프에 넣지 않는다.** 실행 로그/보고에 건수만 남긴다.
