# Research: code_summary 프롬프트 환각·쓰기누락 방지

Phase 0 — Technical Context의 미해결 항목 및 설계 결정 근거. (탐색적 실측으로 대부분 검증 완료.)

## 결정 1 — 환각 방지: 하위(자식/하위 함수) [핵심] 충실 계승

- **Decision**: 부모(호출 함수) summary는 하위 노드(dbms=자식 구문, framework=하위 함수 callee)의 [핵심]이 명시한 처리 축·대상을 충실히 계승하고, 근거 없이 다른 도메인 개념으로 치환하지 않는다(환각 금지). 단서 충돌 시 코드 동작·하위 [핵심]을 우선.
- **Rationale**: 실측 — 권역 합계 MERGE(129)는 코드상 "광역 합계"(RDIB2EN 상위태그별 하위 합산)이고, **하위 SELECT(131)는 "광역 합계용 태그별"로 정확히 요약**해 부모의 compact body에 들어갔다. 그런데 부모 요약 단계에서 qwen이 그 정확한 하위 요약을 무시하고 "유역별 수종"으로 환각했다(입력 테이블 RDIB2EN이 유역/수종 메타라 거기 끌림). LLM 입력 컨텍스트를 직접 확인한 결과 **컨텍스트는 충분, 모델 한계** → 프롬프트가 "하위 요약 계승"을 강제해야 한다.
- **Alternatives considered**:
  - *상위 모델 재분석(gpt-5.4-mini)*: 환각은 줄겠으나 비용 발생 + 비결정성 잔존. 근본 처방 아님(프롬프트가 약하면 어느 모델도 흔들림).
  - *검색기 측 우회(후보텍스트에 R/W·쓰기동작 주입)*: 후보밖 케이스엔 무력하고 summary 자체 품질은 안 고침 = 땜질(사용자 지적). 폐기.
  - → **프롬프트 정정이 근본**(무료·재분석마다 적용·다운스트림 전파). 채택.

## 결정 2 — 쓰기누락 방지: 쓰기 노드 [핵심]에 쓰기 동작·대상 필수

- **Decision**: writes 있는 INSERT/UPDATE/MERGE/DELETE는 [핵심]에 "무엇을 어느 대상에 기록/반영/갱신/삽입"을 반드시 포함. SELECT/USING이 본문 대부분이어도 노드 본질은 쓰기.
- **Rationale**: 실측 — 쓰기 노드 88개 중 7개(8%)가 [핵심]에 쓰기 동작을 누락("조회해 준비"·"조인한다"·"집계한다")했고, 그 8%가 임베딩 검색 실패 케이스와 정확히 일치. 원인은 친화 프롬프트("SQL 키워드 X·의미 우선", 커밋 96950aa)가 `INSERT INTO ... SELECT` 복합문에서 읽기/의도를 앞세우게 유도.

## 결정 3 — 대상 의미어 + 입력→출력 종합

- **Decision**: 쓰기 대상도 테이블명 그대로(`RDD01DD_TB`) 아닌 의미어("일보")로. 가능하면 "어느 입력 테이블에서 읽어 → 어느 대상에 쓰는지"를 한 문장에 종합.
- **Rationale**: summary는 사람용 글(헌법 외 기존 [1.1]·[2.1] "테이블명 그대로 X"와 일관). 권역 회복 summary가 "RDD01DD_TB에 반영"으로 테이블명을 노출한 것은 지침 미준수 → 명확화 필요. 입력→출력 종합은 흐름 식별을 명확히(검색·계약 소비처에 유리). **이 둘은 잔여 미적용 항목** — 본 feature의 핵심 신규 구현.

## 결정 4 — 예시 범용화

- **Decision**: 프롬프트 예시에서 특정 도메인 고유명사(K-water "유역·일보")를 제거하고 범용 표현("대상 테이블·집계 테이블")으로.
- **Rationale**: dbms 프롬프트는 RWIS 외 PL/SQL에도 쓰임 → 도메인 과적합 예시는 부적절. 실측 — **범용 예시로 재분석해도 권역이 "광역 합계"로 동일 회복** → 지침이 근본 효과이며 예시 의존이 아님을 증명.

## 결정 5 — 전략 일관성 + KV-cache 정합

- **Decision**: dbms·framework 양 전략에 같은 원칙 반영(용어만 전략별: dbms=자식, framework=하위 함수 callee). 공유 `_common` 수정분은 `prompt_hashes.json` SHA256 재핀.
- **Rationale**: 헌법 V(KV-cache byte-identical) — `_common`은 3-split 공유 prefix. 분할 간 일관은 유지되나 prefix 내용이 바뀌므로 hash 미갱신 시 CI(`byte_identical.yml`) 실패. 상호 충돌은 필드별 층위 분리(단계1=표현/쓰기동작=의미/단계4=계승)로 회피.
