# Data Model: code_summary 프롬프트 환각·쓰기누락 방지

> 본 feature는 프롬프트 지침 강화로, 새 데이터 스키마(node label/edge type)를 만들지 않는다. 아래는 지침이 다루는 **기존 엔티티**와 그 관계·검증 규칙이다.

## 엔티티

### 코드노드 summary (대상 산출물)
- **필드**:
  - `[핵심]`: 한 줄. 노드의 비즈니스 의미(쓰기 노드면 쓰기 동작·대상 포함, 대상은 의미어).
  - `내용`: 분기·조건·임계값·도메인 코드값 보존(선택, 단순 노드는 생략).
- **소유**: 모든 코드노드(라벨=antlr type: SELECT/INSERT/UPDATE/MERGE/IF/LOOP/CALL …)에 1개.
- **소비처**: robo-architect 설계 계약(노드 분류·rule owner), 임베딩 검색(seed/CE/심판의 텍스트 근거).

### 하위 [핵심] (계승 권위)
- **정의**: 부모(호출 함수) 요약 시 compact body에 들어오는 **자식 구문(dbms)/하위 함수(framework callee)**의 [핵심] 한 줄.
- **규칙**: 부모는 이 [핵심]의 처리 축·대상을 **계승**(치환·누락 금지). 부모 [핵심]은 자식이 정확히 명시한 도메인 개념과 모순되면 안 된다.

### 쓰기 노드 (writes 보유 노드)
- **정의**: `writes` 관계가 있는 INSERT/UPDATE/MERGE/DELETE.
- **규칙**: [핵심]에 쓰기 동작(기록/반영/갱신/삽입/삭제) + 대상(의미어)이 반드시 드러나야 한다.

## 관계 (전략별)

| 관계 | dbms | framework |
|---|---|---|
| 부모↔하위 | 부모 구문 -[PARENT_OF]→ 자식 구문(compact body 합본) | 호출 함수 -[CALLS]→ 하위 함수(callee_summaries) |
| 계승 대상 | 자식 [핵심]의 처리 축·대상 | 하위 함수 [핵심]의 처리 축·대상·반환 의미 |
| 입력→출력 | 자식 SELECT가 읽는 입력 테이블 → 부모 쓰기 대상 테이블 | 하위 함수 R/W·반환 → 호출 함수 처리 |

## 검증 규칙 (Success Criteria 매핑)

- 부모 [핵심]이 하위 [핵심]의 처리 축과 모순되지 않음 → SC-001(환각 0).
- 쓰기 노드 [핵심]에 쓰기 동작 존재 → SC-002(누락 0%).
- 쓰기 대상이 테이블 식별자가 아닌 의미어 → FR-004.
- 도메인 고유명사 없는 범용 예시로도 SC-001 성립 → SC-003.

## 상태/불변

- 본 feature는 노드 라벨·엣지 타입·출력 Pydantic 스키마를 **변경하지 않는다**(헌법 VI·Cross-Service Contracts 불변). summary는 노드 **값**일 뿐 스키마가 아니다.
