# Feature Specification: 요구사항→레거시 코드 뭉치 검색 API (아키텍트 연동)

**Feature Branch**: `main` (spec dir: `044-cluster-search-api`)

**Created**: 2026-07-10 (실측 확정본으로 개정)

**Status**: Draft

**Input**: 아키텍트 Proposal 에서 자연어 요구사항을 입력하면 관련 레거시 코드 뭉치를 참고자료로
받는다. analyzer UI 에도 같은 검색창을 둔다. 검색 로직은 저장소에 단 한 벌, 놀이터
(`module_test/임베딩서칭/`, .gitignore)에 갇힌 현 상태를 정식 배선으로 옮긴다.

## 배경 — 전부 2026-07-10 실측으로 확정된 전제

- **품질 근거**: 위험질의 게이트 SKT 7/7 · 쇼핑몰 11/11 (spec 043 후, 해피패스 0). 이 성적은
  **BGE-M3(1024d) + 강화텍스트(이름·논리명·역할·테이블관계·요약·search_text)** 조합의 것.
- **임베딩 계산처 = 사내 SGLang 서버** (`/v1/embeddings`, `model=BAAI/bge-m3`): 로컬과 벡터
  사실상 동일(코사인 0.99998, 질의 순위 완전 일치 — 게이트 성적 그대로 유효), 서버가 정규화
  제공, 기밀 사내·과금 0. 이 PC 는 GPU 없음(1만 노드 로컬 171분 → 서버 43초).
- **서버 제약(실측)**: 거부(424)는 건수가 아니라 **요청 총 토큰** 기준이며 **부하 의존적**
  (같은 요청이 되기도/안 되기도). 동시 16·문자예산 700 이 실패 0 최속(124노드 0.54초).
  동시 24 이상은 실패 폭증. → 토큰예산 동적 배치 + 동시 전송 + 분할·백오프 재시도 필수.
- **dense 채널 = Neo4j 벡터 인덱스**(그래프 DB 원리): 전량 로드+파이썬 코사인은 데모(124)에서만
  성립하고 실규모에서 붕괴. Neo4j 2026.04 enterprise, 기존 벡터 인덱스 6개(HNSW·COSINE) 운용 중.
- **공통 라벨 부재**: framework 는 FUNCTION 공통이나 dbms 는 구문 라벨(SELECT/MERGE…) —
  전략 공통 라벨 없음. → **마커 라벨 `EMBEDDED`**(벡터 보유 표식, embed_step 이 부여)로 통일,
  인덱스 1개. 라벨 열거·전략 분기 없음(새 전략 자동 포함).
- **라벨 위치 계약**(spec 033/035): `labels[0]`=종류, `labels[1:]`=역할. 프론트는 위치로 자르되
  **마커 제외 장치**(EXTERNAL) 보유 — EMBEDDED 를 마커 집합에 추가(프론트 단일 유틸 1곳).
  아키텍트는 `labels[0]`/포함검사만 사용 → 영향 0 확인.
- **소비자 = 2**: ① 아키텍트(Claude Code 스폰 + `.mcp.json` 주입 경로 실재 — 백엔드 직접 호출
  코드는 없음) ② analyzer UI 검색창. MCP 는 소비자가 아니라 ①의 통로.
- **현 MCP(stdio)는 임시 배선**: 놀이터 venv 절대경로 하드코딩·로직 직접 보유·모델 중복 로드.
  → analyzer 가 **MCP over HTTP** 를 직접 노출하고 stdio 서버는 폐기.
- **검색용 생성 LLM = gpt-5.4-mini 유지**(사용자 결정, GPU 판단력 우려) — 분석용과 **별도 env**.
  사내 GPU 전환은 TODO(전환 시 심판·번역 성적 재측정).
- **후처리 병렬**: 임베딩 재료 의존 = 분석(코드노드) + 테이블설명(테이블). 용어사전 재료 의존 =
  모듈요약. 서로 독립 → **(용어사전 ∥ 임베딩)** 2층 병렬(상한 43초 절감, 실절감은 서버 경합
  실측 후 판정). 서버 총 동시수는 공유 세마포어로 통제.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 아키텍트가 요구사항으로 참고 코드를 받는다 (Priority: P1)

Proposal 작성자가 자연어 요구사항("주문 처리 시 재고 상태 변화")을 입력하면, 아키텍트가 띄운
Claude Code 가 MCP 도구로 검색을 호출해 관련 코드 뭉치(호출관계로 엮임)를 참고자료로 붙인다.

**Why this priority**: 이 기능의 존재 이유.

**Independent Test**: MCP 도구 호출(또는 검색 API 직접 호출)에 요구사항 문장을 넣고 기존
골드(위험질의)로 정답 노드 포함을 확인.

**Acceptance Scenarios**:

1. **Given** 분석 완료(임베딩 저장)된 그래프, **When** 요구사항 문장으로 검색, **Then** 관련
   코드 노드(이름·역할·요약·읽고쓰는 테이블·호출관계·관련도·core/related)와 진단 메타(채택
   보조질의)가 반환된다.
2. **Given** 무관한 문장, **When** 검색, **Then** 빈 뭉치 또는 소수만 반환(곁가지 무더기 금지).
3. **Given** 임베딩 없는 그래프, **When** 검색, **Then** "임베딩 없음" 명시적 오류(빈 결과를
   성공으로 위장 금지).

---

### User Story 2 - 검색 품질이 이식 전후로 동일하다 (Priority: P1)

놀이터 성적이 정식 코드(벡터 출처 .npz→Neo4j 인덱스)로 옮긴 뒤에도 재현된다.

**Why this priority**: 재현 안 되는 이식은 새 시스템이다. 특히 HNSW 는 근사 탐색이라 정답
누락 가능성을 실측으로 배제해야 한다.

**Independent Test**: 이식 코드 + DB 벡터로 두 코퍼스 게이트 재실행.

**Acceptance Scenarios**:

1. **Given** 이식된 검색 + 저장된 임베딩 + 벡터 인덱스, **When** 게이트 실행, **Then**
   SKT ≥ 7/7 · 쇼핑몰 ≥ 11/11.
2. **Given** 같은 질의, **When** 인덱스 검색 vs 전량 코사인 비교, **Then** 상위 후보 집합이
   게이트에 영향 없는 수준으로 일치(정답 누락 0).
3. **Given** 질의·노드 임베딩 모델이 다른 설정, **When** 기동, **Then** 기동 실패(조용한
   오검색 금지).

---

### User Story 3 - 임베딩이 분석 끝에 빠르게·무손실로 채워진다 (Priority: P2)

분석이 끝나면 코드 노드(및 테이블·컬럼) 임베딩이 자동 생성·저장되고 `EMBEDDED` 마커가 붙는다.
대규모 코퍼스에서도 실용적 시간에 끝난다.

**Independent Test**: 두 코퍼스 재분석에서 임베딩 손실 0·차원 동일·소요시간 확인.
재임베딩 CLI 로 재분석 없이 벡터만 재생성 가능 확인.

**Acceptance Scenarios**:

1. **Given** 분석 완료, **When** 임베딩 실행, **Then** 대상 노드 전건 벡터+`EMBEDDED`(손실 0,
   차원 전건 동일).
2. **Given** 서버 거부(413/424), **When** 임베딩 실행, **Then** 분할·백오프로 흡수, 최종 실패는
   오류로 표면화(조용한 건너뜀 금지).
3. **Given** 기존 그래프, **When** 재임베딩 CLI 실행, **Then** 재분석 없이 벡터·라벨·인덱스가
   재구성된다.

---

### User Story 4 - 검색 로직이 저장소에 한 벌만 존재한다 (Priority: P2)

analyzer UI·Claude Code(MCP)가 같은 검색 코어를 쓰고, 놀이터 stdio MCP 서버는 폐기된다.

**Acceptance Scenarios**:

1. **Given** analyzer 의 MCP over HTTP, **When** `.mcp.json` 을 URL 방식으로 등록해 도구 호출,
   **Then** REST 직접 호출과 동일 결과.
2. **Given** 저장소 검색, **When** 검색 알고리즘 정의를 찾으면, **Then** analyzer 정식 코드
   한 곳뿐(MCP 는 같은 코어 함수 호출).

---

### Edge Cases

- 임베딩 서버 다운 → 임베딩·검색 모두 명시적 오류(로컬 CPU 폴백 금지 — 171분 실측, 사실상 행).
- 노드 텍스트 1건이 서버 한도 초과 → 절단하되 로그(조용한 절단 금지).
- 질의 공백 → 400.
- 임베딩 부분 커버리지 → 있는 노드로 검색하되 커버리지를 응답 메타에 표기.
- 옛 그래프(EMBEDDED 없음) → 검색은 "임베딩 없음" 오류, 프론트 표시(종류/역할)는 무변화.
- EXTERNAL stub 은 summary 가 없어 임베딩 대상 아님 → EMBEDDED 와 겹치지 않음.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001 (검색 API)**: analyzer 서버는 자연어 요구사항 → 관련 코드 뭉치 REST 엔드포인트를
  제공해야 한다(반환: 노드 요약·테이블 관계·호출관계·관련도·역할 + 진단 메타 + 임베딩 커버리지).
- **FR-002 (MCP over HTTP)**: analyzer 서버는 같은 검색 코어를 MCP(HTTP transport)로도 노출해야
  한다. 놀이터 stdio MCP 서버는 폐기하고, `.mcp.json` 등록은 URL 방식으로 대체된다. 검색
  알고리즘 사본은 저장소에 1개여야 한다.
- **FR-003 (임베딩 생성·마커)**: 분석 파이프라인은 분석 후 코드 노드 임베딩을 생성해 그래프에
  저장하고 **`EMBEDDED` 마커 라벨**을 부여해야 한다. 임베딩 입력 텍스트는 검색 기대 조성과
  글자 단위 동일해야 한다. 테이블·컬럼 임베딩은 기존 속성 체계 유지.
- **FR-004 (벡터 인덱스)**: dense 후보 탐색은 `EMBEDDED` 라벨 벡터 인덱스(1024d·cosine)로
  수행해야 한다(전량 로드·전수 코사인 금지). 인덱스는 없으면 생성(IF NOT EXISTS)하고,
  **분석 run 은 인덱스가 ONLINE 이 된 뒤 종료**해야 한다(검색은 분석 완료 후에만 일어나므로
  준비 대기는 run 안에서 끝난다). dense 채널은 인덱스 경로와 전량 경로를 한 곳에서 교체할 수
  있어야 한다(SC-002 원복 대비).
- **FR-005 (전송 규율)**: 임베딩 요청은 토큰예산 동적 배치(건수 고정 금지) + 동시 전송으로
  하고, 거부(413/424/429)는 분할·지수 백오프로 흡수, 최종 실패는 raise(손실 0). 서버 총
  동시수는 파이프라인 공유 세마포어를 경유해 통제한다.
- **FR-006 (모델 일치 불변식)**: 질의 임베딩과 노드 임베딩의 공급자·모델이 다르면 기동/요청을
  거부해야 한다.
- **FR-007 (설정 분리)**: 임베딩(`ROBO_EMBED_*`)과 검색용 생성 LLM(`ROBO_SEARCH_LLM_*`)은
  분석용 LLM 설정과 별도 env 로 분리한다.
- **FR-008 (파이프라인 배치)**: 임베딩 step 은 테이블설명 완료 직후 시작할 수 있어야 하며,
  용어사전 종합과 병렬 그룹으로 배치한다(둘은 상호 독립 — 실절감은 구현 후 실측, 이득 없으면
  순차 원복).
- **FR-009 (라벨 계약)**: `EMBEDDED` 는 역할(stereotype)이 아닌 마커다. 프론트 라벨 유틸의
  마커 제외 집합에 추가한다(**교차서비스: frontend 1곳**). `labels[0]` 위치는 불변.
- **FR-010 (게이트웨이)**: `/robo/search/**`(+MCP 경로)를 analyzer(5502)로 라우팅하는 규칙을
  catalog 포괄 규칙보다 앞에 추가한다(**교차서비스: api-gateway 1곳**).
- **FR-011 (재임베딩 CLI)**: 재분석 없이 저장된 분석 결과로 임베딩·마커·인덱스만 재구성하는
  CLI 를 제공한다.
- **FR-012 (범용성 제약)**: 특정 라벨 열거·형태 규칙·전략 분기 금지. 판단(뭉치 선별)은 기존
  검색 코어, 기계 작업(인덱스·전송·저장)은 결정론.

### Key Entities

- **코드 뭉치(cluster)**: 검색 반환 단위 — 관련 노드들 + 호출관계 + 진단 메타.
- **EMBEDDED 마커**: "검색 벡터 보유" 표식 라벨. embed_step 이 부여, 벡터 인덱스의 대상,
  화면에서는 역할로 표시되지 않음(EXTERNAL 과 같은 마커 부류).
- **검색 설정**: `ROBO_EMBED_PROVIDER/MODEL/API_BASE/CONCURRENCY/CHAR_BUDGET` +
  `ROBO_SEARCH_LLM_CONFIG/API_KEY`.

## Success Criteria *(mandatory)*

- **SC-001 (무회귀 관문)**: 이식 코드 + DB 벡터 인덱스로 게이트 SKT 7/7 · 쇼핑몰 11/11 재현.
  실패 시 이후 단계 진행 금지.
- **SC-002 (인덱스 리콜·원복 조항)**: 인덱스 탐색이 전량 코사인 대비 골드 정답을 누락하지
  않아야 한다. 현 코퍼스(38·124노드)는 후보 수(100)와 규모가 비슷해 판별력이 없으므로,
  **합성 대규모(1만·10만 노드)에서 recall@k 를 실측**한다. 미달 시 다이얼을 순서대로 적용:
  ① 후보 k 확대(CE 가 재채점하므로 흡수) ② 인덱스 파라미터를 정확도 쪽으로 ③ **셋 다
  미달이면 전량 코사인 경로로 원복**(사유·수치를 measure_log 에 기록). 눈대중 통과 금지.
- **SC-003 (임베딩 성능·무손실)**: 두 코퍼스 재분석에서 손실 0·차원 동일, 1만 노드 환산 1분
  이내(실측 43초 기준).
- **SC-004 (연동 성립)**: `.mcp.json` URL 등록으로 Claude Code 가 검색 도구 호출 성공 + analyzer
  UI 검색창 실물 동작(Playwright).
- **SC-005 (로직 단일·stdio 폐기)**: 저장소에 검색 알고리즘 1벌, 놀이터 stdio MCP 서버 제거.
- **SC-006 (계약 안전)**: 프론트에서 EMBEDDED 가 역할로 표시되지 않음(실물 확인) ·
  text2sql/catalog 기존 벡터 인덱스·속성 무변화.
- **SC-007 (불변식)**: 임베딩 모델 불일치 설정 시 기동 거부.
