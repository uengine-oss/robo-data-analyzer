**지침의 구조**임이 확인돼 전면 재작성했다.

**현재 증상 (2026-08-07 시점)**
1. framework 프롬프트 재작성은 성공했고 정확도가 전 축에서 개선됐다(§6 F-A).
2. 그러나 **검증의 3층 중 2·3층 상당 부분이 실행된 적이 없었다.** 04 문서에 절차가 완비돼

## 5. 전체 배선: 입력 → 변환 → 저장 → 소비자

```
[framework 경로]
C 소스 (project\data\source, 23파일)
  → parser AST (project\data\analysis, 23 JSON)         [antlr-code-parser, HEAD 42e671b]
  → step2 framework_reader : AST → CodeNode(+expression/target/operator)
  → step5 링커            : DB 입출력 키 리터럴 → READS/WRITES 엣지(dml_type=구문 사실)
  → step6 build_context   : ast_statements/ast_call_lines/table_op 를 ctx.extra 로 주입
                             ★ table_op = "관계가 op 를 결정한다"(§13 수리 2)
  → 분기표 build_inventory() … 답할 자리 5,210행 결정론 생성
  → 행 증거 rule_evidence() … conditions(C##)/effects(E##)/rows(when,direct)
  → 프롬프트 조립 [system(고정) → user_template_specific(고정, 계약 포함) → 증거(가변)]
                             ★ KV 순서: 불변 앞, 가변 뒤 (§6 F-K)
  → LLM 응답 {R###: {cond:[refs], then:[refs], extra:[], nl:"문장"}}
  → 결정론 채점 rule_grading … cond==when? 필수 ret 포함? 실패 시 좌표별 격리
  → 통과분만 RULE 노드 + EXAMPLE(코드가 결정론 합성) → Neo4j
  → 소비자: 아키텍트가 그래프에서 함수-규칙-예시-테이블-호출을 읽는다

[DBMS 경로 — 현재 끊긴 지점]
PLSQL 소스 → parser AST → step2 dbms_reader
                             ★ 여기서 parser statement 계약(expression/target/operator)을
                               전혀 소비하지 않는다 → StatementFact 0
  → build_control_inventory 의 분기 대장 퇴화 → 의무 행 0
  → rule 프롬프트가 rows:{} 로 나감 → 응답도 빈 맵 → findings 0 으로 조용히 통과
```

**KV 캐시 규칙 (중요, 2026-08-06 정정됨)** — 접두사 재사용은 앞에서부터 일치하는 만큼만
된다. 따라서 **불변(고정 계약)은 맨 앞, 가변(대상·행 증거)은 맨 뒤**다. 이 순서는 테스트가
강제하고(`tests/pipeline/step7_analyze_code/test_semantic_generality_contract.py::
test_each_rule_places_fixed_contract_before_variable_target_input`),
`llm/runners/prompt_rules.py`가 고정 절에 가변 placeholder 가 들어오면 예외를 던진다.

**위반이 되는 것 / 아닌 것**
- 위반 O — 고정 절에 가변값을 넣기, 고정 절을 가변부 뒤로 옮기기.
- 위반 X — **고정 절의 내용을 바꾸기.** 바꿔도 전 콜이 같은 접두사를 공유하며 비용은
  run당 프리필 1회뿐이다. 실측: system 532바이트 + user 앞 2,070바이트가 747콜 전부 동일.

09 §5 의 옛 서술 "계약 파일을 고치면 코퍼스 전체 캐시가 무효화된다(실측

`pipeline/execution/run_executor.py:474-480` 의 **analyzer 자체 응답 캐시**이고 공식 cold 는
`ROBO_LLM_RESPONSE_CACHE=false` 로 끄고 돌므로 항상 0.0% 다. 계약을 건드리지 않은 K6 로그에도
`calls: 1314 · rate: 0.0%` 가 있다. **서버 KV 재사용은 우리 쪽에서 측정할 수단이 없다**가
정확한 서술이다(08 §9의 "API `cached_tokens` 는 항상 0" 반증과 일치).

**"지침은 최소 토큰"도 오독이다(2026-08-07 사용자 확정).** 최소화 대상은 **입력의 노이즈와

  DBMS=`neo4j`** 로 분리한다(04 §4.6). 기본 DB 에는 비교 기준선이 있고 실행은 대상 DB 를
  비우고 새로 채우므로 덮이면 되돌릴 수 없다.
- **canonical 코퍼스**(`분석대상모음`): 읽기·복사 자유. **새 AST 생성으로 덮어쓰기는
  사용자 승인 후.** 특히 `apascrt00010t02_20260406\analysis` 는 구 AST 비교 기준선이다.
- **dirty WIP**: `reset`/`checkout`/`clean` 금지. 워크스페이스 루트의 goal-verify 변경분은
  사용자 것이다.
- **커밋·푸시**: 커밋은 이번 세션에 사용자 지시로 수행했다. **푸시는 하지 않았다** —
  푸시는 명시 지시가 있을 때만.
- **삭제**: `logs\` 는 run 별 폴더 + 자동 보존(기본 2)이므로 손으로 지우지 않는다.
  보관소 파일 이동·삭제는 원본이 어디 있는지 확인한 뒤에만.

### 17.1 프롬프트 템플릿 (2026-08-07 서칭 결론 — 사용자 승인, 재작성 시 이 틀을 따른다)

**철학** — 입력(지침 제외)=노이즈 0·구조화 / 출력=누락 없이 중복 0 / **지침=길이 아끼지 않고

**서칭 결론 5개**
1. **형식은 문법이, 의미는 프롬프트가** — 둘은 독립 문제. 형식 강제는 추론 품질을 깎으므로
   스키마는 평평하게 유지하고 의미 지시는 프롬프트가 진다. `response_format` 의 스키마는
   모델에게 설명이 아니므로 **출력 필드 서술을 프롬프트 본문에도** 둔다.
2. **예시가 설명을 이기고, 위치는 앞** — 예시 블록은 프롬프트 앞쪽이 가장 안정적이다.
   lost-in-the-middle 대비로 핵심 규칙은 앞+끝(체크리스트) 이중 배치. 가변 데이터는 맨 뒤
   — KV 순서 요구와 일치하므로 상충이 없다.
3. **하지 마라보다 해라** — 부정 지시는 **대체 행동 + 실물 예시**와 짝으로만.
4. **지시·데이터 격리 + 절마다 적용 필드 명시** — 경계가 없으면 지시가 번진다.
5. **환각 억제 3문장** — "제공된 증거만 사용" + "입증 안 되면 지어내지 말고 원문 그대로" +
   "원문 값 보존". 근거가 없을 때의 **행동을 정의**해 준다.
- 주의: 중형 오픈모델은 복잡한 다단계 지시망을 다 못 따른다. 디테일하되
  **한 절 = 한 필드 = 한 작업**의 단순 구조를 유지한다.

**조립 순서**
```
[SYSTEM 불변]   역할 + 출력 용도 한 문단
[USER 고정부]   §A 임무 개요 → §B 입력 명세(필드별 1줄) → §C 출력 명세(필드별 절:
```
