# Feature Specification: DRY·단일진실 복원 — 헌법 II·III 준수 (동작 불변 리팩터)

**Feature Branch**: `046-dry-single-truth`

**Created**: 2026-07-13

**Status**: Draft

**Input**: 2026-07-13 DRY 전수조사(`docs/작업보고내용/2026-07-13-analyzer-DRY조사.md`)에서 확정된 **구조 중복**. spec 045 가 "동작이 틀린 것"을 고쳤다면, 046 은 **동작을 바꾸지 않고 중복을 없앤다.**

---

## 배경 — 왜 이 스펙인가

헌법(`.specify/memory/constitution.md`)이 못박은 두 원칙이 코드에서 지켜지지 않고 있다.

| 헌법 조항 | 위반 사실 (실측) |
|---|---|
| **II. Zero-Branch Strategy** — *"`graph_builder` assembles … with **no strategy `if` branches**"* | `analyze_code_step` 안에 `strategy.name == "dbms"` **하드분기**. 레포 스스로 `graph_builder` docstring 에 *"같은 step 인데 처리 방식 다름? → DI"* 라 적어놓고 위반 |
| **III. Single Source of Truth** — *"Each cross-cutting fact has exactly one home"* | 지원 확장자 **2벌**(4종 vs 14종 — 불일치) · "루틴이 무엇인가" **2벌**(METHOD 유무) · LLM 비용추적 **2벌 구현 + 1곳 누락** · Neo4j 저장 쿼리 **32벌** · 소스 슬라이싱 **3벌** · 노드 공통 8필드 **5벌** |

**핵심**: 이 중복들은 지금 당장은 대부분 무해하지만, **새 노드 종류·새 언어·새 전략을 추가할 때마다 N곳을 복붙**해야 하고 한 곳만 빠뜨리면 조용히 갈라진다. 실제로 이미 갈라진 증거가 둘 있다 — 확장자(4 vs 14), 루틴 라벨(METHOD 유무).

**부수 효과**: 저장 계층 통합(FR-004)이 끝나면, spec 045 가 미룬 **소유권 기반 그래프 삭제**(analyzer 노드만 지우기)가 MERGE 단일 지점에 **1줄**로 들어간다. 지금은 13곳을 고쳐야 해서 못 한다.

---

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 새 노드 종류를 추가할 때 한 곳만 고친다 (Priority: P1)

개발자가 새 노드 종류(예: 새 언어의 새 선언 타입)를 추가할 때, **저장 코드 한 곳**만 손대면 된다. 지금은 13개 파일에 흩어진 거의 동일한 저장 쿼리 중 하나를 복붙해야 하고, 빠뜨리면 조용히 안 저장된다.

**Why this priority**: 저장 계층은 그래프의 진실을 만드는 곳이다. 여기 중복이 있으면 **모든 후속 기능이 그 중복을 상속**한다. 또한 이 통합이 끝나야 소유권 기반 삭제(045 가 미룬 것)가 가능해진다.

**Independent Test**: 저장 쿼리 정의 개수를 센다. 통합 전 32개 → 통합 후 1개(+정당한 예외). 그리고 분석을 돌려 **그래프가 통합 전과 완전히 동일**한지 대조한다.

**Acceptance Scenarios**:

1. **Given** 통합 후 코드, **When** 분석 실행, **Then** 만들어지는 그래프(노드 수·라벨·속성)가 **통합 전과 완전히 동일**하다.
2. **Given** 통합 후 코드, **When** 저장 쿼리 정의를 전수 조사, **Then** 노드 저장의 일반 경로는 **한 곳**이다.

---

### User Story 2 - 전략이 늘어도 step 안에 `if` 가 생기지 않는다 (Priority: P1)

새 분석 전략을 추가할 때 **파이프라인 선언 한 곳**만 고치면 되고, step 함수 안에 `if 전략 == X` 가 늘지 않는다.

**Why this priority**: 헌법 II 가 명시적으로 금지한 것이며, 레포 자신의 `graph_builder` 문서가 해법(DI)까지 적어놨는데 지켜지지 않고 있다. 분기가 step 안에 숨으면 **전략별 동작 차이가 코드 전역에 흩어진다**.

**Independent Test**: step 함수들에서 `strategy.name == ...` 형태의 분기를 전수 검색한다. 0건이어야 한다. 그리고 두 전략 모두 결과가 종전과 동일한지 확인한다.

**Acceptance Scenarios**:

1. **Given** 리팩터 후 코드, **When** step 함수에서 전략 이름 비교 분기를 검색, **Then** **0건**이다.
2. **Given** 리팩터 후 코드, **When** DBMS·Framework 두 전략으로 각각 분석, **Then** 결과가 종전과 동일하다.

---

### User Story 3 - 같은 사실이 두 곳에서 다르게 정의돼 있지 않다 (Priority: P1)

"어떤 확장자를 지원하는가", "무엇이 루틴인가" 같은 사실이 **정확히 한 곳**에만 정의된다.

**Why this priority**: **이미 갈라져 있다.** 지원 확장자가 한 곳은 4종, 다른 곳은 14종이다. 그 결과 `.kt`/`.go`/`.ts` 프로젝트는 전략 판정은 통과하고 파싱에서 전부 스킵되어 **노드 0개짜리 분석이 "성공"으로 끝난다.**

**Independent Test**: 지원하지 않는 확장자만 있는 프로젝트로 분석을 시도한다. 0노드 성공이 아니라 **명시적 실패**여야 한다.

**Acceptance Scenarios**:

1. **Given** `.kt` 파일만 있는 프로젝트, **When** 분석 실행, **Then** "지원하지 않는 언어"로 **명시적으로 실패**한다 (0노드 성공 금지).
2. **Given** 리팩터 후 코드, **When** 확장자 정의를 전수 검색, **Then** **한 곳**에만 있다.
3. **Given** 리팩터 후 코드, **When** "루틴 라벨" 정의를 전수 검색, **Then** **한 곳**에만 있고 `METHOD` 를 포함한다.

---

### User Story 4 - 같은 파일을 여러 번 읽지 않는다 (Priority: P2)

한 번의 분석에서 **같은 소스 파일을 반복해서 디스크에서 읽지 않는다.**

**Why this priority**: 지금은 같은 파일을 한 run 에서 **최소 5회~8회+** 읽는다. 캐시가 step 마다 새로 만들어져 무력화되고, 이미 메모리에 있는 원문(`code_text`)을 두고 디스크에서 다시 잘라낸다. 낭비이자, "원문의 진실이 어디인가"가 흐려진다.

**Independent Test**: 분석 1회에서 같은 파일을 읽는 횟수를 계측한다. 파일당 1회여야 한다.

**Acceptance Scenarios**:

1. **Given** 리팩터 후, **When** 분석 1회 실행, **Then** 각 소스 파일의 디스크 read 는 **1회**다.
2. **Given** 리팩터 후, **When** 분석 결과 비교, **Then** 그래프·산출물이 종전과 동일하다.

---

### User Story 5 - LLM 비용이 전부 계측된다 (Priority: P2)

LLM 을 호출하는 모든 경로의 토큰·비용이 **계측되고 예산 한도의 적용을 받는다.**

**Why this priority**: 검색 기능은 질의마다 심판·재작성 LLM 을 호출하는데 **비용 추적 코드가 0건**이다. 헌법의 "$400 사고 방지" 회로차단기가 이 경로엔 아예 안 걸린다.

**Independent Test**: 검색 질의를 1회 실행하고 사용량 기록에 그 호출이 남는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 리팩터 후, **When** 검색 질의 1회 실행, **Then** 그 LLM 호출의 토큰·비용이 사용량 기록에 남는다.
2. **Given** 리팩터 후, **When** LLM 호출 경로를 전수 조사, **Then** 비용추적이 **한 곳**에 구현돼 있고 모든 경로가 그것을 지난다.

---

### User Story 6 - 죽은 코드가 없다 (Priority: P3)

아무도 부르지 않는 함수·모듈, 아무도 읽지 않는 설정 키가 코드베이스에 남아있지 않다.

**Why this priority**: 읽는 사람을 오도한다 (예: 마스킹 on/off 설정이 있는데 실제로는 **항상 마스킹**한다 — 설정이 거짓말을 한다).

**Independent Test**: 삭제 대상 심볼을 4개 레포에 전수 grep 해 참조 0건임을 확인하고 삭제한다. 분석이 정상 동작하면 성공.

**Acceptance Scenarios**:

1. **Given** 삭제 후, **When** 분석 실행, **Then** 정상 완주한다.
2. **Given** 삭제 후, **When** 참조 검색, **Then** 삭제한 심볼의 참조가 0건이다.

---

### Edge Cases

- **통합이 동작을 바꾸면 안 된다**: 모든 리팩터는 **그래프·산출물이 종전과 동일**해야 한다. 다르면 리팩터가 아니라 회귀다. (단 045 가 의도적으로 바꾼 부분은 045 기준선을 쓴다.)
- **합치면 안 되는 것**: 도메인이 실제로 다른 곳(DBMS 의 실행흐름 워커 vs Framework 의 역할 워커 / 두 분석 엔진의 노드 우주 정의)은 **합치지 않는다.** 중복 제거가 목적이지 동일화가 목적이 아니다.
- **라벨은 antlr type 직결을 유지**: 저장 통합 시 `label = node["type"]` 연결이 끊기면 프론트의 라벨·색상이 전부 회귀한다.

## Requirements *(mandatory)*

### 헌법 II — 분기 0 복원

- **FR-001**: 코드 분석 단계에서 **전략 이름을 비교하는 하드분기를 제거**하고, 전략이 자기 분석 구현체를 **주입**하는 방식으로 바꾼다. (레포 자신의 `graph_builder` 규약: *"같은 step 인데 처리 방식 다름? → DI"*)
- **FR-002**: 두 전략의 **분석 엔진은 유지**한다 (노드 우주 정의가 실제로 다르다 — 하나는 컨텍스트 전체, 하나는 skip-투명 유효트리). **`if` 만 걷어내는 것**이 목표이지 엔진 통합이 아니다.

### 헌법 III — 단일 진실 복원

- **FR-003**: **지원 확장자**의 정의는 한 곳이어야 한다. 전략 판정과 실제 파싱이 **같은 목록**을 봐야 한다. 지원하지 않는 확장자만 있는 프로젝트는 **명시적으로 실패**해야 한다 (0노드 성공 금지).
- **FR-004**: **Neo4j 노드 저장**의 일반 경로는 한 곳이어야 한다. 라벨별로 거의 동일한 저장 쿼리를 복붙하지 않는다. **정당한 예외**(테이블처럼 `coalesce` 보존 로직이 필요한 경우)는 예외임을 명시한다.
- **FR-005**: **"무엇이 루틴인가"** 의 정의는 한 곳이어야 하며 `METHOD` 를 포함해야 한다.
- **FR-006**: **LLM 비용추적**은 한 곳에 구현되고 **모든 호출 경로**가 그것을 지나야 한다. 검색용 LLM 호출도 계측 대상이다.
- **FR-007**: **소스 원문 슬라이싱**은 한 곳에서만 계산한다. 이미 메모리에 있는 원문(`code_text`)이 있으면 **디스크에서 다시 읽지 않는다.**
- **FR-008**: **소스 파일 캐시**는 **분석 1회 범위**에서 공유되어 같은 파일을 여러 번 읽지 않는다.
- **FR-009**: AST 리더의 **노드 공통 필드 계산**(식별자·이름·파일·라인·라벨·주석)은 한 곳에서만 한다.

### 코드 위생

- **FR-010**: **참조 0건**임이 4개 레포 전수 검색으로 확인된 죽은 코드를 삭제한다. 특히 **효과 없는 설정 키**(있는데 코드가 무시하는 것)는 읽는 사람을 속이므로 반드시 제거한다.
- **FR-011**: LLM 병렬 호출의 **예외 분류 로직**(예산초과는 전파 / 그 외는 로그+집계)이 9곳에 복붙돼 있다. 한 곳으로 모은다.

### 동작 불변 (이 스펙의 안전장치)

- **FR-012**: 위 모든 변경은 **동작을 바꾸지 않는다.** 같은 입력에 대해 **그래프와 산출물이 리팩터 전과 동일**해야 한다. 다르면 회귀로 간주하고 되돌린다.

### Key Entities

- **저장 계층**: 노드/관계를 그래프에 기록하는 코드. 라벨별 차이는 **데이터**(어떤 필드를 담나)여야 하고 **코드 복제**여서는 안 된다.
- **전략(Strategy)**: 분석 파이프라인 변형. 차이는 **선언**에 있어야 하고 step 내부 분기에 있어서는 안 된다.
- **온톨로지**: "무엇이 루틴인가", "어떤 확장자를 지원하나" 같은 **분류 지식**. 코드 상수가 아니라 데이터로 산다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: **동작 불변** — 리팩터 전후로 그래프(노드 수·라벨별 분포)와 산출물이 **동일**하다. (가장 중요한 기준.)
- **SC-002**: step 함수에서 **전략 이름 비교 분기 0건**.
- **SC-003**: 노드 저장 쿼리 정의가 **1개**(+명시된 정당한 예외)로 줄어든다. (현재 32개)
- **SC-004**: 지원 확장자 정의가 **1곳**. 미지원 확장자만 있는 프로젝트는 **명시적 실패**(0노드 성공 0건).
- **SC-005**: "루틴 라벨" 정의가 **1곳**이고 `METHOD` 포함.
- **SC-006**: 한 분석에서 같은 소스 파일의 디스크 read **1회**. (현재 5~8회)
- **SC-007**: 검색 LLM 호출의 토큰·비용이 **사용량 기록에 남는다**. (현재 0건)
- **SC-008**: 삭제한 죽은 심볼의 참조가 4개 레포에서 **0건**이고 분석이 정상 완주한다.
- **SC-009**: LLM 예외 분류 로직 정의가 **1곳**. (현재 9곳)

---

## Assumptions

- **동작 불변이 최우선**: 어떤 통합도 결과를 바꾸면 안 된다. 판단이 애매하면 **합치지 않는다** — 중복 제거보다 회귀 방지가 우선이다.
- **합치지 않는 것 (도메인이 진짜 다름)**: DBMS 의 실행흐름 워커 vs Framework 의 역할 워커 / 두 분석 엔진의 노드 우주 정의 / 테이블 저장의 `coalesce` 보존 로직 / 노드 라벨의 antlr type 직결.
- **045 선행**: 045 가 산출물 바이트를 이미 바꿨으므로, 046 의 "동작 불변"은 **045 이후 상태**를 기준선으로 한다.
- **소유권 삭제는 046 이후의 선택지**: FR-004(저장 통합)가 끝나면 analyzer 소유 노드만 지우는 삭제가 1줄로 가능해진다. 다만 **이번엔 도입하지 않는다** — 045 에서 "전부 삭제"를 제품 결정으로 채택했다. 필요해지면 그때 별도 스펙.
