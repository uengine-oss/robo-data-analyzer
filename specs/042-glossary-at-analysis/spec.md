# Feature Specification: 용어사전 원천화 (glossary at analysis)

**Feature Branch**: `042-glossary-at-analysis` | **Created**: 2026-07-09 | **Status**: Draft
**Input**: 사용자 확정 설계(2026-07-09) + 실측 근거(놀이터 measure_log Session 16~17) — 용어집을 검색기가 켜질 때 LLM으로 창작하는 현 구조는 ① 별칭·뜻이 재생성마다 변동(복권 — SK-VAN 별칭 '결제망' 유무로 7/7↔4/7 2회 재현) ② 첫 검색 지연(LLM 배치) ③ 요약만 보고 역추측(전달게임). 근본 = 용어 지식의 원천(분석 시점, 코드 원문을 보는 유일한 순간)에서 뽑아 저장.

## User Scenarios

### US1 - 분석 중 용어 조각 수집 (P1)
분석기가 함수를 분석할 때(분할1) 그 함수에 등장하는 **도메인 약어·시스템명과 그 뜻**을 함께 뽑아 노드에 저장한다. 뜻은 ⓐ 일반 업계 의미(무엇의 약자/어떤 부류인지 — 세상지식) ⓑ 이 코드에서의 역할 순으로. 조각이 없으면 빈 값.

### US2 - 후처리 종합 (P1)
분석 후처리 단계(기존 병렬 step 묶음에 편입)에서 전 노드의 조각을 모아 **사전 완성본**을 만든다: 같은 용어에 뜻이 여러 개 쌓이면 병합, 진짜 다의어는 나란히 보존. 완성본은 그래프에 저장(검색기가 read-only로 읽음).

### US3 - 검색기 소비 전환 (P2)
검색기 용어집은 그래프의 완성본을 **읽기만** 한다(LLM 생성 단계 소멸 → 첫 검색 지연 0, 복권 소멸). 완성본이 없는 옛 그래프에서는 기존 생성 경로로 폴백. 질의 처리 3단 사다리(글자 대조→의미 대조→AI 잇기)는 기존 구현(spec 008) 그대로 이 완성본 위에서 동작.

## Functional Requirements

- **FR-001**: 분할1 출력에 **용어 조각 필드**(가칭 domain_terms, "약어=뜻; 약어=뜻" 평탄 단일 문자열 — 폭주 차단 원칙) 추가. framework·dbms 양 전략 동일. 코드에 실재하는 약어·시스템명·핵심 코드값만(창작 금지), 뜻에는 일반 업계 의미 포함.
- **FR-002**: 후처리 신설 step 이 전 노드 조각을 결정론 파싱·수집 후 종합(동일 canonical 병합, 다의어 병렬 보존 — LLM 배치 1콜 이내)해 그래프에 저장한다. 기존 후처리 step 들과 **병렬** 실행(파이프라인 선언 1곳, 분기 0).
- **FR-003**: 놀이터 glossary 는 그래프 완성본 우선 로드, 부재 시 기존 생성 폴백. 사용자 별칭 창작은 저장하지 않는다 — 별칭 잇기는 질의 시점(3단 사다리)의 몫.
- **FR-004**: 게이트 — 재분석 후 양 DB 위험질의에서 현행(검색기 생성 용어집) 대비 **동등 이상** + 잔여 경계 2건(c200·d700) 개선 관측 시 성공. 반복 재생성 변동(복권) 소멸 확인(같은 그래프에서 용어집 재현 = 결정론 로드).
- **FR-005**: KV 캐시(공통 system 불변 — 분할 고유 지침만)·해시 장부·프론트 비노출(domain_terms 도 search_text 와 동일 취급) 준수.

## Success Criteria

- **SC-001**: 위험질의 양 DB 동등 이상(유실 0) — SKT 5/7+·쇼핑몰 11/11 유지.
- **SC-002**: 용어집 로드가 결정론(같은 그래프 → 같은 사전, LLM 0) + 첫 검색 용어집 지연 소멸.
- **SC-003**: 분석 비용 — LLM 호출 증가 = 후처리 종합 1콜 이내(분할1은 필드 추가만).

## Assumptions

- 저장 형태(그래프 내 단일 GLOSSARY 노드 vs 용어 노드들)는 plan 에서 확정 — 소비자(놀이터·MCP)는 read-only Cypher 1개로 로드 가능해야.
- c200·d700 은 서술 변동 문제도 겹쳐 있어 완전 회수는 미보장 — 개선 관측이 기준(정직).
