# Feature Specification: 실시간 분석 진행 스트림 + 전략무관 일관 보기모드

**Feature Branch**: `refactor` (전용 브랜치 미생성 — 기존 WIP 보존)

**Created**: 2026-06-19

**Status**: Draft

**Input**: User description: "분석 실행 중 비-LLM 시스템 step(DDL·AST·링킹)이 끝나는 즉시 그 산출물(노드·관계)이 화면 트리·그래프·콘솔에 라이브로 채워지고, 분석 후 보기모드(영역/건강/모듈간)가 framework·dbms 전략 무관하게 동일하게 동작. '모았다 한 번에' 금지."

## 배경 (확정된 현재 결함 — 전수조사 근거, 추측 아님)

분석은 antlr 파싱 → analyzer 파이프라인(여러 step) → Neo4j → 화면 순으로 흐른다. 현재 화면 진행 표시가 다음과 같이 깨져 있다:

- **골격이 한 번에 나타남**: 그래프 노드/관계를 라이브로 화면에 보내는 일을 **마지막 LLM 분석 step 하나만** 한다. 그 앞의 시스템 step들(테이블/컬럼 추출, 코드 구조 적재, 관계 링킹)은 결과를 저장만 하고 화면엔 안 보낸다 → 분석이 다 끝난 뒤에야 한꺼번에 등장.
- **콘솔 멈춤**: step별 진행 로그가 콘솔로 흐르지 않아 "분석 시작"에서 멈춘 것처럼 보인다.
- **관계 0**: 분석 중 화면에 표시되는 관계가 0으로 고정(라이브로 오는 관계가 전부 화면 비표시 종류).
- **카운트 불일치**: 진행 패널의 "노드 수"가 실제 노드 수와 다르다(이벤트 누적 개수를 셈).
- **보기모드 빈 화면**: 영역/건강/모듈간 보기를 켜면 데이터가 있는데도 그래프가 비거나 한 점으로 뭉친다(대량 그래프를 그릴 때 자동 배치가 동작 안 함). framework·dbms 어느 전략이든 동일하게 동작해야 하는데 그렇지 않다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 분석 진행이 실시간으로 화면에 채워진다 (Priority: P1)

분석을 시작하면, 각 시스템 단계(DDL 파싱·코드 구조 적재·관계 링킹)가 **끝나는 즉시** 그 단계가 만든 노드와 관계가 좌측 트리·그래프·우측 통계에 라이브로 나타난다. 마지막 AI 분석 단계는 노드 하나가 분석될 때마다 즉시 갱신된다. 콘솔에는 단계별 진행 메시지가 끊김 없이 쌓인다.

**Why this priority**: 사용자(비개발자 분석가)의 핵심 불편. 진행이 안 보이면 분석이 멈춘 건지 도는 건지 알 수 없어 신뢰가 깨진다. 5회 시도에도 미해결된 최우선 통증.

**Independent Test**: 분석을 실행하고, 첫 시스템 단계가 끝나는 시점에 트리/그래프에 그 단계 산출물이 보이는지, 콘솔에 메시지가 흐르는지, "노드 수/관계 수"가 0에서 증가하는지 관찰. AI 단계 없이 시스템 단계만으로도 화면이 채워지면 통과.

**Acceptance Scenarios**:

1. **Given** 분석 시작 직후, **When** DDL 파싱 단계가 끝나면, **Then** 그 단계가 만든 테이블·컬럼 노드와 그 사이 관계가 화면(트리·그래프·통계)에 즉시 나타난다.
2. **Given** DDL 단계 완료 후, **When** 코드 구조 적재 단계가 끝나면, **Then** 파일·루틴 등 코드 노드와 소속·부모 관계가 즉시 추가된다.
3. **Given** 링킹 단계가 끝나면, **When** 읽기/쓰기/호출 관계가 만들어지면, **Then** 그 관계가 즉시 그래프와 관계 수에 반영된다(관계 수가 0이 아니다).
4. **Given** 분석이 진행 중, **When** 각 단계가 끝날 때마다, **Then** 콘솔에 해당 단계 완료 메시지가 실시간으로 한 줄씩 쌓인다.
5. **Given** framework 전략이든 dbms 전략이든, **When** 분석을 실행하면, **Then** 위 라이브 채워짐 동작은 동일하다(내용만 다름).

---

### User Story 2 - 보기모드가 전략 무관하게 일관 동작한다 (Priority: P2)

분석이 끝난 뒤 "영역/건강/모듈간" 보기모드를 켜면, 데이터가 있는 한 그래프가 항상 제대로 보인다(노드가 펼쳐져 배치되고 영역 경계가 노드를 감싼다). framework·dbms 어느 전략이든 같은 방식으로 동작하며 내용(노드 종류·수)만 다르다.

**Why this priority**: 직전 변경 이후 "원래 되다가 갑자기 안 뜸"으로 회귀한 기능. 분석 결과 해석의 핵심 도구라 신뢰 회복 필요. P1(라이브) 다음.

**Independent Test**: 분석 완료 후 모듈간/영역/건강 보기를 각각 켜고, 해당 데이터를 가진 노드가 화면에 펼쳐져 보이는지 확인. dbms 데이터와 framework 데이터 각각에서 동일하게 동작하면 통과.

**Acceptance Scenarios**:

1. **Given** 분석 완료(데이터 로드됨), **When** "모듈간 상호작용" 보기를 켜면, **Then** 모듈과 테이블 노드가 펼쳐져 보이고 그 사이 사용 관계가 그려진다(빈 화면·한 점 뭉침 금지).
2. **Given** 분석 완료, **When** "영역" 보기를 켜면, **Then** 영역(컴포넌트) 정보를 가진 노드가 펼쳐져 보이고 같은 영역끼리 색 경계로 감싸진다. 해당 노드가 없으면 안내가 표시된다.
3. **Given** 분석 완료, **When** "건강" 보기를 켜면, **Then** 위험도 정보를 가진 노드가 펼쳐져 보이고 위험도별 색으로 강조된다.
4. **Given** 같은 보기모드, **When** framework 결과 vs dbms 결과에서 각각 켜면, **Then** 동작·표시 규칙이 동일하다(내용만 다름).
5. **Given** 어떤 보기모드든, **When** 노드가 여러 개 한 번에 표시되면, **Then** 노드가 서로 겹치지 않게 자동 배치되어 읽을 수 있다.

---

### User Story 3 - 화면 카운트가 실제와 일치한다 (Priority: P3)

진행 패널·통계의 "노드 수 / 관계 수"가 실제 화면에 반영된 고유 노드/관계 수와 일치한다(중복 이벤트·비표시 항목을 세지 않는다).

**Why this priority**: 신뢰도 문제지만 기능 차단은 아님. P1·P2 정합 후 마무리.

**Independent Test**: 분석 후 표시된 노드/관계 수와 패널 카운트를 비교해 일치하는지 확인.

**Acceptance Scenarios**:

1. **Given** 분석 진행/완료, **When** 진행 패널의 노드 수를 보면, **Then** 실제 표시 중인 고유 노드 수와 같다(중복·비표시 제외).
2. **Given** 비표시로 지정된 노드 종류가 존재할 때, **When** 카운트를 보면, **Then** 그 종류는 노드 수에도 그래프에도 일관되게 빠진다.

---

### Edge Cases

- 어떤 시스템 단계가 산출물 0건이면? → 빈 emit은 화면을 바꾸지 않고 콘솔엔 "완료(0건)" 정도로 흐른다. 오류 아님.
- 분석 도중 중단/일시정지하면? → 그 시점까지 라이브로 받은 골격은 화면에 남는다(깜빡임 없이).
- 보기모드에서 해당 속성을 가진 노드가 0개면? → 빈 화면 대신 "표시할 노드 없음" 안내(현행 동작 보존).
- 같은 노드가 여러 단계에서 갱신되면(예: 골격 후 LLM 보강)? → 라이브 병합은 덮어쓰기(중복 노드 생성 금지), 카운트는 고유 1개.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 각 비-LLM 시스템 단계는 자신이 만든 노드·관계 전량을 **그 단계 완료 시점에 즉시** 화면 스트림으로 내보내야 한다(다음 단계로 넘어가기 전).
- **FR-002**: 단계별 스트림 내보내기는 두 전략(framework·dbms) 모두에서 동일하게 동작해야 한다 — 단계 구성이 전략별로 달라도 내보내기 방식은 공통이어야 한다(중복 구현 금지).
- **FR-003**: 라이브로 내보내는 구조 관계(소속·부모·읽기·쓰기·호출 등)는 화면 트리·그래프에 즉시 반영되어야 하며 "비표시"로 걸러지지 않아야 한다.
- **FR-004**: 각 단계 진행/완료 시 사람이 읽을 수 있는 진행 메시지가 콘솔에 실시간으로 누적되어야 한다.
- **FR-005**: 분석 중 표시되는 관계 수는 실제 라이브로 들어온 표시 가능한 관계가 있으면 0이 아니어야 한다.
- **FR-006**: 진행/통계 카운트는 실제 고유 노드/관계 수(중복 제거, 비표시 제외) 기준이어야 한다.
- **FR-007**: 보기모드(영역/건강/모듈간)는 한 번에 다수 노드를 표시할 때 노드가 자동 배치되어 겹치지 않고 보여야 한다(빈 화면·한 점 뭉침 금지).
- **FR-008**: 보기모드는 framework·dbms 전략 무관하게 동일한 규칙으로 동작해야 한다(같은 속성·관계 기준, 내용만 다름).
- **FR-009**: 보기모드에서 영역 경계(같은 그룹 감싸기)는 노드 위치와 어긋나지 않게 따라 그려져야 한다(줌·팬·드래그·자동배치 중에도).
- **FR-010**: 보기모드 대상 노드가 0개면 빈 화면 대신 안내를 표시해야 한다(침묵 금지).
- **FR-011**: 같은 노드가 여러 단계에서 들어와도 화면엔 고유 1개로 병합되어야 한다(중복 생성·깜빡임 금지).
- **FR-012**: 분석 완료 후 최종 그래프는 라이브로 쌓인 내용과 정합해야 한다(완료 시점에 누락된 골격이 없도록 보정 가능).

### Key Entities *(include if feature involves data)*

- **진행 이벤트(스트림)**: 분석 중 화면으로 흐르는 단위 신호. 종류 = 단계 진행/완료, 노드 생성/갱신, 관계 생성/갱신, 진행 메시지.
- **그래프 노드**: 테이블·컬럼·파일·루틴·구문 등. 종류(타입)와 식별자, 표시 속성을 가짐. 일부 종류는 화면 비표시.
- **그래프 관계**: 소속·부모·읽기·쓰기·호출 등 구조 관계(표시) + 규칙/예시/흐름 등 비표시 관계.
- **보기모드**: 영역(컴포넌트 그룹)·건강(위험도)·모듈간(모듈↔테이블 사용)·기본. 한 번에 하나(상호배타).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 분석 시작 후 **첫 시스템 단계 완료 시점(수 초 내)** 에 화면 트리·그래프에 노드가 보이기 시작한다(분석 끝까지 기다리지 않는다).
- **SC-002**: 분석 진행 중 콘솔 메시지가 **단계마다 한 줄 이상** 실시간으로 늘어난다("분석 시작"에서 멈추지 않는다).
- **SC-003**: 분석 진행 중 표시 관계 수가 **0이 아니다**(구조 관계가 만들어진 시점 이후).
- **SC-004**: 진행 패널 카운트가 실제 표시 고유 노드/관계 수와 **100% 일치**한다.
- **SC-005**: 모듈간/영역/건강 보기를 켜면 해당 데이터가 있는 한 **100% 그래프가 보인다**(빈 화면 0).
- **SC-006**: 동일 보기모드를 framework·dbms 결과에서 각각 켰을 때 **동작·표시 규칙이 동일**하다.
- **SC-007**: 회귀 0 — 기존 드래그-드롭 캔버스, 1-hop 확장, 노드 패널, 일시정지/재개가 그대로 동작한다.

## Assumptions

- 노드 라벨/속성 모델(spec 019/020)·식별자 통일(017)은 이미 완료·변경 없음. 본 스펙은 그 모델 위에서 **표시·스트림**만 다룬다.
- framework·dbms 두 파이프라인 모두 컴포넌트 군집화·건강지표 단계를 거쳐 영역(component_id)·건강(risk_level) 속성을 **같은 키로** 생성한다(코드 확인됨).
- 보기모드의 "정답 기준"은 기존 NVL+오버레이 프로토타입(기본 자동배치 + 연속 동기) 동작이다.
- 게이트웨이↔카탈로그 연결 끊김(현재 모든 그래프 조회 실패)은 **인프라 배선 문제로 본 스펙 범위 밖** — 라이브 검증 전 별도 복구 전제.
- 진행 스트림 전송 인프라(단일 채널·즉시 흘림)는 정상이며 변경 대상이 아니다. 결함은 "단계가 내보내기를 호출하지 않음"에 있다.

## 범위 밖 (Out of Scope)

- 게이트웨이/카탈로그 인프라 배선 복구.
- 노드 라벨/속성/식별자 모델 변경.
- 새 보기모드 추가, 새 분석 단계 추가.
