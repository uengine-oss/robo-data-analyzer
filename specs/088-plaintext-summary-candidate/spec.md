# 088 — code_summary 를 평문+결정론 파싱으로 전환 (후보 — 승인 대기)

작성: 2026-07-23. spec 087 이 밝힌 문법 비용(평문 대비 3.2배)에 대한 **유일하게 남은
클라이언트측 대응**이다. spec 080 이 스칼라 한줄요약에 이미 적용한 패턴
("문법 강제 제거 + 결정론 형식 검증")을 `code_summary` 로 확대한다.

## 파일럿 실측 (run11 적재본의 실제 프롬프트 6건을 그대로 재사용 — 동일 입력)

| 방식 | 벽시계 | 출력 토큰 | 처리량 | 필수필드 충족 |
|---|---:|---:|---:|---|
| 현행 구조화(function_calling) | 5.8초 | 1,445 | 247 토큰/초 | 6/6 |
| **평문 5줄 + 결정론 파서** | **3.2초** | 862 | 265 토큰/초 | **6/6** |

- 벽시계 **1.8배** 단축. 이득의 대부분은 처리량이 아니라 **출력 토큰 40% 감소**에서 온다
  (JSON 골격·필드명·따옴표가 사라짐). 즉 "덜 만들기"가 아니라 "포장을 안 만들기"다.
- 형식 준수 실패 0건. 요약 내용은 육안상 동등 이상(오히려 더 구체적인 사례 관측).

## 예상 효과

`code_summary` 는 run17 에서 416콜·지연합 8,938초(step7 LLM 합의 31%)다. 1.8배면
지연합 ≈ 4,970초 절감 → step7 516초 → **약 440초**, 총 **약 600초 = 10분**.
목표선에 정확히 걸린다.

## 왜 아직 착수하지 않았나 — 승인이 필요한 이유

이 변경은 **제품의 모든 함수 요약 문구를 바꾼다**(그래프·검색·UI 노출 텍스트). GOAL 제약은
"LLM 산출물은 품질 동등 이상, 판정 근거가 없으면 gold set(층화 50~100함수)을 먼저
만들어라"이므로 절차는 다음과 같다:

1. gold set 구축 — 층화 표본 50~100함수의 기대 요약·역할·논리명을 원문 대조로 작성
   (`분석대상모음\<프로젝트>\gold`, [[answer-key-policy]]).
2. 평문 계약 확정 — 5줄 형식, 접두사 고정, 파서의 실패 처리(형식 위반 시 구조화 1회 폴백).
3. 구현 + 단위테스트(파서의 정상·누락·순서변경·다국어 입력) + 전수 회귀.
4. 전체 실행 → 결정론 산출물 6종 정확 일치·완주 416/416 확인 + gold set 대조로
   품질 동등 이상 판정. 미달이면 원복.

**리스크**: 형식 준수는 파일럿 6/6 이었으나 416건 전량에서의 실패율은 미지수다. 실패 시
구조화 폴백이 필요하고, 폴백률이 높으면 이득이 사라진다. 또한 요약 문구 변경은
검색 임베딩·UI 표시에 파급되므로 되돌리기 비용이 있다.

## 2차 실측 — 규모 형식 준수율 (최대 리스크 해소)

정답지 작업 전에 "416건 규모에서 형식을 지키는가"부터 깼다. run11 적재본의 **실제 프롬프트
60건**을 그대로 재사용(동일 입력), 동시 32:

| 지표 | 결과 |
|---|---|
| 5줄 전부 준수 | **59/60 (98%)** |
| 핵심(요약+역할) 확보 | **60/60 (100%)** |
| 처리량 | 463 토큰/초 (구조화 동일 조건 241 → **1.9배**) |

형식 미준수 1건도 핵심 필드는 확보됐다. 구조화 폴백을 붙이면 실패 경로가 닫힌다.

## 정답지 — 층화 표본 50 확보, 그러나 **1차 지표는 무효**

`분석대상모음\apascrt00010t02_20260406\gold\summary_facts.json` 에 역할×크기×테이블접촉
35개 층에서 뽑은 50함수와 원문 추출 사실(반환코드·리터럴·테이블 425개), 기준선 요약을 넣었다.

**그러나 "요약에 그 사실들이 나타나는가"로 점수를 매긴 것은 잘못된 척도였다.** 실측 결과
기준선(구조화) 0.0% · 평문 2.9% 로 둘 다 바닥이었는데, 원인은 품질 저하가 아니라 **제품이
요약에서 코드 토큰을 의도적으로 배제**하기 때문이다(프롬프트 규칙 "코드 식별자 X",
세부 코드값은 `search_text` 담당). 즉 이 지표는 제품 계약과 반대 방향을 재고 있었다.

**올바른 판정 척도(다음 단계)**: 제품이 이미 가진 요약 품질 계약을 쓴다 —
`summary_quality.enforce_summary_boundary` 의 규칙형 판정 통과율(run17 기준 재작성
59/416 = 14%)과 `logical_name`·`stereotype` 유효성. 평문 전환본의 재작성률이 14% 이하이고
역할 유효율이 동등하면 제품 기준으로 품질 동등 이상이다. 의미 판단이 더 필요하면 표본
50건을 원문과 함께 사람이 읽는다.

## 최종 판정 — **기각 (품질 미달, 2회 시도)**

올바른 척도(제품 자신의 `summary_boundary_reasons` 경계 게이트)로 층화 표본 50건을 재봤다:

| 시도 | 경계 위반(규칙형 요약) | 역할 유효 | 5줄 준수 |
|---|---:|---:|---:|
| 기준선(구조화) | **2/50 (4%)** | — | — |
| 평문 1차 | 20/50 (40%) | 50/50 | 59/60 |
| 평문 2차(스키마 필드 계약을 지시문에 이식) | **12/50 (24%)** | 50/50 | 50/50 |

계약 문구를 그대로 옮겨도 기준선의 **6배**다. 구조화의 규율은 설명 문구가 아니라 **필드
경계 자체**에서 나온다 — JSON 이 `summary` 와 `search_text` 를 물리적으로 가르는 반면
평문은 한 덩어리라 모델이 조건·수치를 요약에 섞는다.

위반분은 `enforce_summary_boundary` 가 재작성해 최종 품질은 보정되지만, 그만큼 LLM 콜이
늘어(추정 +40여 콜) 속도 이득을 깎고, 무엇보다 **초안 규율이 6배 나빠진 것을 "동등 이상"
이라 부를 수 없다.** 프롬프트 변형을 더 돌리는 것은 수렴이 불확실한 튜닝이라 여기서 끊는다.

## 상태

**기각.** 속도 이득(1.9배)·형식 안전성(98~100%)은 사실이나 품질 제약을 통과하지 못했다.
정답지(50함수)와 판정 절차는 남겨두어 다음 시도가 같은 척도로 즉시 판정할 수 있게 한다.
1차 지표 실패(코드 토큰 반영률)도 그대로 남긴다 — 잘못된 척도를 다시 쓰지 않기 위해서다.
