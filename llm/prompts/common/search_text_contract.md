## search_text 책임 — 모든 언어·도메인 공통

`search_text`는 사용자가 구현 이름을 모르더라도 이 루틴을 자연어로 찾게 하는 검색용 설명이다.
본문에서 확인되는 **주요 동작, 입력·대상, 산출물·반환, 상태 변경·외부 호출·I/O 같은 관측 효과**를
1~2문장으로 쓴다. 검색 결과를 구별하는 대표 조건·상태 전이·경계가 중요하면 방향과 원문 값을
보존한다. 모든 분기와 값을 나열하지 않으며 상세 회계는 `rules/examples`가 담당한다.

분석 대상으로 제공된 모든 루틴은 `search_text`를 채운다. 분기가 없거나 단순 위임·변환·초기화·
조회·접근자라는 이유로 비우지 않는다. 본문 없는 선언이나 빈 구현도 빈 문자열로 두지 말고
"본문 없이 시그니처만 선언한다", "관측 가능한 동작 없이 즉시 반환한다"처럼 입력에서 확인되는
구조적 사실을 쓴다. 함수/프로시저 이름만으로 숨은 업무 의미를 추측하지 않는다.

좋은 예와 잘못된 예:

- 잘못: 본문이 입력을 직렬화해 외부 전송기로 넘기는데, 조건 분기가 없다는 이유로 `""`.
- 좋음: "입력 객체를 전송 형식으로 직렬화해 외부 전송기에 전달하고 그 처리 결과를 반환한다."
- 잘못: 본문 없는 선언을 모델이 임의로 "의미 없음"이라 판정해 `""`.
- 좋음: "본문 없이 호출 규약과 반환 형식만 선언한다."
- 잘못: 실제 조건은 "상한보다 크면 거부"인데 "상한 이하이면 거부"로 방향을 뒤집음.
- 좋음: "입력 값이 상한보다 클 때 요청을 거부하고, 그 이하는 다음 처리로 전달한다."
- 잘못: 주석 처리된 예전 분기를 현재 동작으로 설명하거나, 본문에 없는 업무 명칭을 덧붙임.
- 좋음: 활성 본문에서 관찰되는 동작과 값만 설명하고, 비활성·주석 코드는 제외함.
- 잘못: "상황에 따라 적절히 처리한다"처럼 검색어와 결과를 복원할 수 없는 문장.
- 좋음: 조건과 관측 결과가 있으면 각각 명시하고, 없다면 루틴의 실제 변환·위임·I/O 효과를 명시함.

용어 목록이나 `용어=뜻` 사전을 쓰지 않는다. `summary`와 의미·표현이 겹치는 것은 허용하되
차이를 만들려고 근거 없는 세부 규칙을 추가하지 않는다. `search_text` 자체는 자연스러운 검색
문장으로 완결한다.
