## FILE / MODULE / CLASS 종합 의미 계약

입력은 이 컨테이너에서 실제 의미 분석 대상으로 선택된 멤버들의 summary다. 구조용 IF·CASE·
LOOP 노드는 입력에 없으며 추측해 복원하지 않는다.

### summary

사용자가 이 파일·모듈·클래스가 무엇을 담당하는지 이해하도록 1~3문장으로 쓴다.
멤버를 한 줄씩 나열하지 말고 공통 목적, 주요 처리 단계, 최종 산출·외부 효과를 종합한다.
멤버에 없는 책임·인과·업종 지식은 추가하지 않는다.

- 잘못: 멤버가 입력 검증과 전송 위임만 하는데 정산·승인 이력 저장까지 추가
- 좋음: “요청을 검증하고 전송 가능한 형태로 구성해 외부 처리에 위임한다.”
- 잘못: 함수별 문장을 그대로 이어 붙인 긴 목록
- 좋음: 여러 멤버가 함께 만드는 모듈 차원의 흐름으로 압축

### logical_name

멤버 전체의 공통 업무 목적이 드러나는 짧은 명사구다. 파일명·클래스명을 번역하거나
“처리 모듈” 같은 일반어만 쓰지 않는다. 근거가 부족하면 빈 문자열이다.

- 잘못: 물리 파일명에서 추측한 “프리미엄 결제 관리”
- 좋음: 멤버가 배송 요청 검증·접수만 입증하면 “배송 요청 접수”

### stereotype

제공된 폐쇄 목록 중 실제 멤버 책임의 중심에 맞는 하나만 글자 그대로 선택한다.
목록 밖 값, 합성값, 번역값을 만들지 않는다.

### 소유권과 정확성

callee 내부 규칙이나 다른 파일 책임을 가져오지 않는다. 멤버 summary에 조건·값이 명시되지
않았으면 모듈 summary에서 새 조건·값을 만들지 않는다. 비교 경계와 단위가 근거에 있으면
그 의미를 바꾸지 않는다.

- 잘못: 멤버에 단순 위임만 있는데 callee의 상세 검증 규칙을 파일 책임으로 승격
- 좋음: 파일이 직접 조율하는 위임 흐름과 관측 효과까지만 종합

출력은 `ModuleSummaryOutput`의 `summary`, `logical_name`, `stereotype`만 포함한다.
