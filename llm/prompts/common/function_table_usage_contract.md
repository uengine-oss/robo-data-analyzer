## Table usage meaning contract

Analyzer가 현재 코드의 직접 테이블 접근을 `(physical_table_id, access_mode)`별 `FT` 항목으로 이미 확정했다. 모델은 구조를 다시 찾거나 고치지 않고, 각 항목이 수행하는 업무 목적만 한 문장으로 쓴다.

## [INPUT GUIDE]

각 `FT` 항목은 다음 정보만 가진다.

- `physical_table_id`: Analyzer가 연결한 실제 테이블. 번역하거나 다른 테이블로 바꾸지 않는다.
- `access_mode`: 확정된 READ 또는 WRITE 방향.
- `occurrences`: 원문에서 이 접근이 발생한 줄, 연산, 실제 사용 컬럼. 여러 발생은 하나의 접근 목적을 함께 입증한다.
- `table_description`: 이미 확정된 테이블 설명이 있을 때만 포함된다. 이름만 보고 의미를 추측하는 대신 원문 해석을 보조한다.
- 번호가 붙은 원문: 조건, 계산, 결과 사용을 확인하는 현재 분석 단위의 정확한 코드다.

## [DECISION]

각 `FT`의 값에는 현재 코드가 해당 테이블과 접근 방향을 사용하는 업무 목적만 쓴다. 테이블 이름의 번역, 구조 정보, 좌표, 상태, 근거 메모, 다른 테이블이나 하위 함수의 효과를 덧붙이지 않는다. 입력만으로 업무 목적을 입증할 수 없으면 빈 문자열을 쓴다.

- 잘못: `고객 테이블을 READ한다`처럼 구조를 복창하거나, 이름만 보고 `고객 인증 정보를 조회한다`고 추측한다.
- 좋음: 원문이 상태 비교에 사용함을 보여줄 때 `서비스 처리 가능 여부를 판단할 고객 상태를 조회한다`처럼 현재 사용 목적만 쓴다.

## [SELF CHECK]

응답 전 다음을 확인한다.

1. 배정된 모든 `FT` key를 정확히 한 번 채웠는가.
2. 각 값이 문자열 하나이며 현재 함수의 실제 사용 목적만 설명하는가.
3. 물리 테이블, 접근 방향, 연산, 컬럼을 변경하거나 응답에 복창하지 않았는가.
4. 입력에 없는 업무 의미를 이름 모양이나 일반 지식으로 만들지 않았는가.
