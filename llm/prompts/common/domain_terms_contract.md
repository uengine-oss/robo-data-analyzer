## domain_terms — 현재 대상마다 10개 절대 상한

현업 사용자가 그 표기 그대로 검색할 고유 용어만 출력한다. `term`은 현재 대상의 코드,
주석 또는 주입된 원문 증거에 연속된 글자로 실제 존재해야 하고, `meaning`의 모든 사실도
같은 증거에서 확인되어야 한다. 약어의 원형·기관 정체·프로토콜 뜻이 없으면 확장하지 않는다.
변수명·함수명·테이블명, 일반 프로그래밍어, 뜻이 설명되지 않은 상태 코드값은 용어가 아니다.

각 항목의 `evidence`에는 `meaning` 전체를 뒷받침하는 현재 대상 원문의 연속된 구절을 글자
그대로 복사한다. `term`만 등장하고 뜻을 설명하는 구절이 없으면 그 항목을 만들지 않는다.
후보 meaning, 함수명, 업계 상식은 evidence가 아니다.

- 허용 개수는 **0~10개**다. **10개는 목표가 아니라 마지노선**이다.
- 후보가 없으면 `[]`가 정답이며 개수를 채우려고 일반어·조합어를 만들지 않는다.
- 후보가 11개 이상이면 아래 우선순위로 **상위 10개**만 선택하고 **10번째에서 배열을 닫는다**.
- 같은 우선순위라면 현재 대상에 먼저 등장한 후보를 선택한다.
- 다른 대상의 용어를 가져오지 않는다.

우선순위:

1. 외부 시스템·기관·망·프로토콜·공식 규격의 고유명
2. 현업이 그대로 질문하는 낯선 업무 약어·업무어
3. 이름 붙은 업무 정책·상태 체계

### 올바른 예시

입력에 공식 명칭과 뜻이 실제로 있으면 다음처럼 근거가 있는 수만 작성한다.

```json
[
  {"term":"<원문의 외부망명>","meaning":"<원문이 밝힌 뜻>","evidence":"<뜻을 밝힌 원문 구절>"},
  {"term":"<원문의 업무상태명>","meaning":"<원문이 밝힌 뜻>","evidence":"<뜻을 밝힌 원문 구절>"}
]
```

후보가 2개이므로 2개에서 끝낸다. 뜻 없는 `A17`, `W01`, `ENC` 같은 값만 있으면 `[]`다.

### 잘못된 예시

```json
[
  {"term":"업무 결과","meaning":"...","evidence":"업무 결과"},
  {"term":"업무 결과 상세","meaning":"...","evidence":"업무 결과"},
  {"term":"업무 결과 상세 코드","meaning":"...","evidence":"업무 결과"},
  {"term":"업무 결과 상세 메시지","meaning":"...","evidence":"업무 결과"}
]
```

원문 표제어가 아니라 한 항목을 계속 늘린 파생 체인이므로 전부 금지한다.

### 10개 경계 예시

실제 고유 후보가 12개면 위 우선순위의 상위 10개만 쓰고 11·12번째는 출력하지 않는다.
후보가 6개면 6개만 쓰며 나머지 4개를 만들지 않는다.
