## Rule leaf 계약

이 계약은 필드별 절로 나뉜다. **각 절은 절 제목에 명시된 필드에만 적용된다.**
한 절의 지시를 다른 필드에 적용하지 않는다.

### 출력 개요

너는 required로 지정된 각 행(R<번호>)마다 규칙 카드 하나를 만든다. 카드는 네 칸이다 —
`cond`(조건 참조), `then`(효과 참조), `extra`(추가 효과), `nl`(사람이 읽는 설명).
이 카드는 원문을 읽지 않는 설계자가 코드의 분기 하나하나를 빠뜨림 없이 파악하는 데 쓰인다.
`cond`/`then`은 기계 검증을 통과해야 하고, `nl`은 사람에게 실제 정보를 주어야 한다.

### 입력 명세 — 행 증거의 구조

- `conditions` : 조건 번호(C##) → 조건 원문. 각 원문은 소스에 실재하는 판정식이다.
- `effects`    : 효과 번호(E##) → 효과 객체(op/target/value). 소스에 실재하는 동작이다.
- `rows`       : 행 번호(R##) → { role, when(그 행까지의 정확한 경로 조건),
                 direct(그 행의 직접 효과 번호들), source(그 행의 원문) }.
- 그 밖의 입력(referenced_symbols, callee_summaries, external_evidence 등)은 의미 이해를
  돕는 참고이며, 출력에 복사하는 대상이 아니다.

### `cond` — 조건 참조 배열

이 절은 `cond`에만 적용된다. 이것은 옮겨 적는 작업이다.

- 해당 행의 `when` 배열을 순서까지 그대로 복사한다. `C12`는 성립, `!C12`는 불성립이다.
- `when:[]`이면 `cond:[]`이다.
- 복사하는 동안 조건의 뜻을 따지지 않는다. 문장으로 옮길 때 의미가 달라 보여도 복사한
  값을 고치지 않는다 — 의미 판단은 `nl` 절에서만 한다.

예시 — `when`이 `["C12","!C15"]`인 행:

- 옳음: `"cond": ["C12","!C15"]`
- 틀림: `"cond": ["!C12","C15"]` — 뜻을 다시 판단해 극성을 바꿨다. 복사가 아니다.

### `then` — 효과 참조 배열

이 절은 `then`에만 적용된다. 이것은 옮겨 적는 작업이다.

- 행의 `direct`에 있는 `E번호`를 빠짐없이 정확히 한 번씩 복사한다. `direct`가 없으면
  `then:[]`이다.
- `effects`가 각 번호의 exact CALL/RETURN/대입을 이미 정의하므로 같은 내용을 객체로
  다시 쓰지 않는다.

예시 — `direct`가 `["E3","E7"]`인 행:

- 옳음: `"then": ["E3","E7"]`
- 틀림: `"then": ["E3"]` — 빠뜨렸다. `"then": ["E3","E7","E9"]` — 이 행의 것이 아닌
  번호를 더했다.

### `extra` — 추가 효과 (보통 빈 배열)

이 절은 `extra`에만 적용된다.

- 기본값은 `[]`이며 대부분의 행이 `[]`이다.
- 다음 두 경우에만, 그것도 현재 행의 증거로 직접 증명될 때만 아래 고정 객체를 추가한다:
  - 오류 발생이 증명됨: `{"op":"raise_error","target":null,"value":null,"from_source":null}`
  - 권위 table op가 증명됨: `{"op":"select|insert|update|delete|upsert","target":"정확한 table ID","value":null,"from_source":null}`
- 함수 이름의 관습이나 일반 지식은 증명이 아니다. 증명이 없으면 `[]`로 둔다.

### `nl` — 사람이 읽는 설명문

이 절은 `nl`에만 적용된다. 이것은 설명하는 작업이다 — 위 세 칸과 달리 여기서는
번호가 가리키는 **내용**으로 말한다.

- `nl`은 이 분기를 처음 보는 사람에게 "어떤 상황에서, 무엇이 일어나는가"를 알려주는
  개행 없는 한 문장이다. 조건 절과 효과 술어 **둘 다** 내용을 담아야 완성이다.
- 조건은 `conditions`에서 번호가 가리키는 원문의 내용으로, 효과는 `effects`에서 번호가
  가리키는 동작의 내용으로 서술한다. 번호 자체(C12, E3)는 문장에 넣지 않는다 —
  번호는 `cond`/`then`이 이미 보존하므로 문장에서 반복하면 중복이다.
- **문장의 술어는 `direct`가 가리키는 효과의 내용이다** — 무엇을 호출·저장·반환·설정
  하는지를 쓴다. 효과를 말하지 않는 술어로 문장을 끝내지 않는다. `direct`가 없는 행은
  효과를 지어내지 말고 아무 효과 없이 지나간다는 사실을 그대로 쓴다.
- 조건이 많으면 전부 나열하지 않는다. 앞선 공통 경로는 한 구절로 묶고, 이 분기를
  형제 분기와 가르는 마지막 조건을 또렷하게 쓴다. 정확한 전체 경로는 `cond`가 진다.
- 원문의 식별자·상태값은 번역하지 않고 원문 그대로 쓴다. 상태값의 업무적 뜻이 입력
  증거로 입증되면 그 뜻을 쓰고 원문 값을 함께 표기한다. 입증되지 않으면 뜻을 지어내지
  말고 원문 값 그대로 서술한다.

예시 — 같은 행(조건: 조회 결과 없음 + 재시도 한도 미달, 직접 효과: 재요청 호출과 상태
저장)에 대한 세 가지 답:

- 나쁨: `조건 C1, C2가 성립하면 E1, E2를 실행한다.`
  — 번호를 문장으로 옮겼을 뿐이다. 번호를 모르는 독자에게 정보가 없다.
- 나쁨: `조회 결과가 없으면 해당 케이스를 처리한다.`
  — 조건은 채웠지만 술어가 비었다. 무엇이 일어나는지 말하지 않는 문장은 미완성이다.
- 좋음: `조회 결과가 없고 재시도 한도에 이르지 않았으면 요청을 다시 보내고 처리 상태를
  대기로 남긴다.` — 조건과 효과 모두 번호가 가리키는 내용을 썼다.

예시 — 경로가 깊은 행:

- 좋음: `앞선 검증을 모두 통과한 뒤 잔액이 요청 금액에 못 미치면 거래를 취소하고 오류
  코드를 반환한다.` — 긴 경로를 묶고, 이 분기를 가르는 조건만 또렷이 남겼다.

### 전역 규칙 — 모든 필드에 적용

- 제공된 증거만 사용한다. 증거 밖 사실을 만들지 않는다.
- 값을 계산·축약·해석하지 않고 실행 결과를 예측하지 않는다. 시스템이 선택된 ref/extra
  객체를 표준 Python Rule 표기로 직렬화한다.
- 어느 필드 절과 이 전역 규칙이 충돌해 보이면 해당 필드의 절이 우선한다.
- Example과 anchor_line은 출력하지 않는다. 키가 anchor 좌표이며 Example은 승인된 Rule에서
  시스템이 파생한다.

### 내보내기 전 자기 점검

- `cond` == 그 행의 `when` 그대로인가 (순서·극성 포함)
- `then` == 그 행의 `direct` 전부, 각 한 번씩인가
- `extra`는 증명 없으면 `[]`인가
- `nl`에 C##/E## 번호가 없는가, 조건 절과 효과 술어 둘 다 내용이 있는가, 한 문장인가
